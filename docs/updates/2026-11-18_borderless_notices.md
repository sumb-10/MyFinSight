# 알림 · 빈 화면 · 버튼 테두리 통일, 사이드바 서버 상태 안내 (2026-11-18)

앱의 메시지·알림 상자를 한 모양(테두리 없음, 토큰 색)으로 맞추고, 사이드바의 서버 상태 안내 문구를 쉬운 말로 바꿨다.
브랜치 `feature/front-home-redesign`, 커밋 `0a192f0`(알림 통일), `e35fd07`(사이드바 안내).
각 항목은 "무엇을 / 왜 / 어디를(파일) / 어떻게 확인했나"를 적는다.

## 1. 문제

- 요청 취소 확인의 빨간 테두리 상자가 「너무 AI 같다」는 의견. 앱 전체 알림이 색 테두리 + 색 면 + 진한 색 글씨였다.
- 같은 오류라도 공용 `Alert`, `ActionError`, 실행 실패 상자, 화면에 직접 쓴 상자(30여 곳)가 조금씩 달랐다.
- 빨강·노랑·초록 계열 클래스(220곳)는 토큰과 이어져 있지 않아 토큰을 바꿔도 따라오지 않았다.
- 사이드바의 「분석 일꾼 꺼짐 — 새 분석이 시작되지 않습니다」는 문장 중간에서 줄이 끊겼고, 「새 분석」·「일꾼」이 무엇인지 알기 어려웠다.

## 2. 결정

- **알림 상자 한 모양**: 테두리 없음 · 둥글기 18px · 면은 연한 토큰 색(안내 `tint` · 주의 `warning-tint` · 오류 `danger-tint` · 성공 `success-tint` · 중립 `sunken`). 제목 `main`, 본문 `body`, **색은 아이콘에만**.
- **바꿀 수 있는 곳은 공용 `Alert` 로 대체**하고, 테스트가 이름으로 찾는 확인 상자(`alertdialog`)처럼 바꾸기 어려운 곳은 같은 색 값(`NOTICE_BOX` · `NOTICE_ICON`)만 쓴다 (사용자 결정: 테두리 지우고 대체할 수 있는 건 공용으로).
- **알림 안 버튼**: 새 `soft`(흰 면 · 테두리 없음). 되돌릴 수 없는 동작(요청 취소 · 중지 확정 · 취소 확정)은 꽉 찬 빨강 `destructive`(토큰 `danger`).
- **빈 화면** `EmptyState`: 테두리 없는 흰 카드 (늘 회색 페이지 위). 공용 `Card` 는 앱의 모든 카드가 쓰므로 그대로.
- **테두리를 남기는 곳**: 고르는 항목·선택 상태, 입력창, 태그·알약, 떠 있는 층(메뉴·말풍선 안내), 흰 카드 위 버튼 — 테두리가 「고를 수 있음/골랐음」이나 경계를 나타낸다.
- **사이드바 안내** (사용자 결정): 제목 한 줄 + 설명 한 줄. 「분석 실행이 멈춰 있어요 / 실행해 두면 기다렸다가 다시 켜지면 자동으로 시작돼요」. 일꾼이 꺼져도 아이디어 해석·질문은 되고 실제 분석 실행만 대기열에서 기다리므로, 무엇이 멈췄는지를 말한다. 실행 화면 안내도 같은 말로.

## 3. 수정

### 화면

- **`ui/index.tsx`**: `Alert`(tone `neutral` 추가, `icon` · `role` · `className` 받음), `NOTICE_BOX` · `NOTICE_ICON` · `NoticeTone`, `Button` 에 `soft`, `destructive` 를 토큰 `danger` 로, `EmptyState` 테두리 없는 카드.
- **공용 Alert 로 대체**: `analysis/flow.tsx`(`ActionError` 14곳 · `ResultNote` · 기다리는 중 · 요청 취소 확인), `run/RunScreen.tsx`(실행 실패), `app/App.tsx`(연습 모드 띠), `paper/KrwPerformance.tsx`(원화 수익률 안내), `analysis/BatchQuestions.tsx`(함께 바뀐 항목 · 바뀐 값 없음). 원래 `Alert` · `ErrorState` 를 쓰던 43곳은 부품만 고쳐 자동으로 바뀜.
- **같은 색 값으로 테두리만 제거**: `ConfirmScreen`(반영하지 않은 추가 요청), `PaperScreen`(중지 확인), `RunScreen`(취소 확인 · 진행 중 단계 · 취소 완료 · 확인할 점 줄), `MessageOutcome`, `report/blocks.tsx`(Callout), `Dashboard`(알림 목록 · 뉴스 반영 효과), `RebalanceCard`, `ProfileScreen`(예상 투자 일정), `profile/compare.tsx`, `TutorialScreen`(예시 안내 · 둘러보기 완료), `report/panels.tsx`(자체 평가 · 검증 메모), `StartPaperDialog`, `RequestHistory`.
- **알림 안 버튼 12개**: `secondary` → `soft`, 확인 상자의 `danger` → `destructive`.
- **`app/App.tsx`**: 사이드바 서버 상태 3개(연결 끊김 · 연습 모드 · 실행 멈춤)를 `SideNote`(알림 모양, 제목 + 설명, 낱말 단위 줄바꿈)로. `run/RunScreen.tsx` 안내 문구를 같은 말로.
- **`home/chatParts.tsx`**: 대화창 경고·오류 말풍선은 일반 말풍선과 같은 회색 면 + 색 아이콘.

### 문서

## 4. 알아 둘 것

- 리포트 삭제 확인의 빨간 버튼도 `destructive` 라 밝은 빨강에서 차분한 진빨강(`#b91c1c`)으로 함께 바뀌었다.
- 노랑·초록 알림 면(`warning-tint` 1.04, `success-tint`)은 흰 카드 위에서 아주 연하다. 색 아이콘으로 구분한다.
- 아직 테두리가 남은 큰 흰 카드(`Card` · 리포트 섹션 · 대시보드 · 실행 화면 카드 등 20여 곳)와 카드 안 작은 상자(20여 곳)는 이번 범위 밖이다. 홈처럼 테두리 없는 흰 카드 · 회색 면으로 바꿀지 결정이 필요하다 (리포트 파일이 많이 바뀌어 팀원 브랜치와 충돌 가능).
- 입력창은 홈만 회색 면이고 다른 화면은 테두리다. 하나로 맞출지 미정.

## 5. 확인

- 이 커밋까지의 상태에서 타입 검사 통과, 화면 테스트 363 통과 (알림을 색 클래스로 찾는 테스트는 없었고, 역할·이름은 유지).
- 실제 서버 화면에서 측정: 예시 리포트 안내 · 빈 화면(「아직 리포트가 없습니다」, 목록 응답만 0개로 바꿔 촬영) · 사이드바 안내의 테두리 0px.
