# MyFinSight 프로젝트 문서

> 작성 기준: 2026-10-03 · 목적: Codex와 함께 기존 서비스의 디자인과 프론트엔드를 개선하기 위한 공통 기준

MyFinSight는 주식 초보자의 투자 아이디어를 개인 조건에 맞는 포트폴리오 전략으로 구체화하고, 과거 성과와 투자 근거를 전문가의 설명처럼 읽을 수 있는 리포트로 제공하는 투자 의사판단 보조 플랫폼이다.

이 문서는 새로운 홈페이지를 만드는 기획서가 아니다. 기존 서비스의 사용자 흐름을 유지하면서 화면 구조, 문장, 데이터 연결과 상호작용을 개선하는 기준이다. 향후 Codex 작업은 아래 문서를 먼저 읽고 진행한다.

## 반드시 유지할 원칙

1. 사용자 조건 확인 후에만 분석을 시작한다.
2. 기본 프로필과 이번 분석 조건을 구분한다. 프로필 변경은 과거 리포트를 바꾸지 않는다.
3. 정성 DB 자료는 기업·산업 판단을, 실제 계산 결과는 비중·성과 수치를 뒷받침한다.
4. 리포트는 상세한 문단형 분석이 중심이고, 표·차트는 그 분석을 지원한다.
5. 리포트 조회만으로 모의투자를 시작하지 않는다. 수정안은 원본과 별개의 결과로 저장한다.
6. 완성된 사용자 화면에 개발 용어와 임시 기능 안내를 남기지 않는다. 실제 실패와 데이터의 출처는 정확히 전달한다.
7. 데스크톱 React 앱을 localhost에서 실행한다. 이번 작업에 원격 배포·클라우드 로그인·동기화를 추가하지 않는다.

## 문서의 적용 범위와 근거

이 문서는 사용자의 최신 디자인 지시와 기존 프로젝트 자료를 통합한다. 화면과 리포트의 표현은 최신 사용자 지시를 우선한다. 과거 문서의 짧은 요약·노란 경고 중심 리포트는 이번 디자인의 기준으로 사용하지 않는다.

검토한 자료는 `상위 요구사항 정리.pdf`, `UC 정리.pdf`, `MyFinSight 프로토타입 모듈 명세 & 분배.pdf`의 범위·주요 모듈 계약, `1. 프로젝트제안서(최종).pdf`이다. 제안서의 여러 시장 지원 구상보다 2026-10-02 UC의 미국 시장 고정을 현재 범위로 사용한다. 모듈 명세의 수치는 기본값·제안·팀 확인 항목을 포함하므로 모두 확정 제품 정책으로 취급하지 않는다.

기존 화면 참고: https://shove-clump-97488458.figma.site

기존 화면의 문제는 앞선 대화에서 확인한 내용을 개선 과제로 정리한 것이다. 이번 문서 작성에서는 사이트를 다시 검수하거나 React 저장소를 수정하지 않았다. 이 작업 공간에는 프로젝트 자료가 있으며 앱 소스가 없어, 실제 프레임워크·컴포넌트 구조·구현 완료 여부는 저장소 연결 후 확인해야 한다.

이 `docs/` 폴더를 MyFinSight 저장소 루트에 넣고 다음처럼 작업을 요청할 수 있다.

> docs/README.md와 연결된 문서를 읽고 기존 구현을 확인하세요. 먼저 보고서 상세 화면을 문단형 투자 리포트로 개선하세요. 기존 사용자 흐름과 로컬 실행 구조를 유지하고, 데이터·출처·표·차트를 일관되게 연결하세요. 수정 결과와 확인한 사용자 흐름을 보고하세요.

문서는 구현 완료를 증명하지 않는다. 구현에서 확인한 사실, 새로 결정한 정책, 남은 이슈가 생기면 해당 문서를 함께 갱신한다.
