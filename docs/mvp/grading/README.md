# MyFinSight 채점표 (루브릭)

작성 2026-10-26. 이 문서는 "프로그램이 설계보고서의 요구사항을 얼마나 만족하는가"를 매기는 기준이다. 채점 **결과**는 날짜가 붙은 파일(`2026-10-26_scorecard.md`)과 시나리오별 기록(`2026-10-26/`)에 있다.

근거 문서:
- 개념설계보고서 「2. 설계사양 > 가. 제품 요구사항」(요구 1~15), 「다. 평가 내용」(평가 방법·기준 원문), 「4. 평가 및 분석 > 가. 평가 기준」(C1~C6 가중치, 5/3/1 채점 규칙)
- 상세설계보고서 「4. 소프트웨어 설계 > ◇ 요구사항 [표 3]」(R1~R15), 「바. 결과 통합과 리포트」(7섹션), [표 2] 성과 지표, [표 7] 검증 게이트, [표 8] 오류 처리
- `docs/module_prototype2.md` §2.1 공통 제약 C-01~C-12 (한국어·금지 표현·결정론·선견 금지의 번호는 여기서 옴)

## 1. 채점 방식 두 겹

| 겹 | 대상 | 척도 | 어디에 적나 |
| --- | --- | --- | --- |
| A. 시스템 채점 | 요구 1~15 (요구 13은 범위 제외 → N/A) | 보고서 방식: 요구마다 **5 / 3 / 1** (5 = 구조로 보장, 3 = 부분 충족이거나 확인 불가, 1 = 구조적으로 보장 못함). 그룹 C1~C6 평균 × 가중치 합 = **/5.00**, 100점 환산 병기 | scorecard §1 |
| B. 시나리오 채점 | 실제로 돌린 시나리오 하나하나 | 10항목 × **0~2점** = 20점 → **100점 환산**. 2 = 요구대로, 1 = 일부·흠, 0 = 안 됨 | 시나리오별 기록 + scorecard §2 |

A 는 "이 프로그램의 구조가 요구를 보장하는가", B 는 "이 입력에서 실제로 그렇게 나왔는가"를 본다. B 의 결과는 A 의 근거로 쓴다.

### 가중치 (개념설계보고서 평가 기준 그대로)

| 그룹 | 뜻 | 들어가는 요구 | 가중치 |
| --- | --- | --- | --- |
| C1 데이터·결과 신뢰성 | DB·코드 계산, 선견 없음, 검증 통과 결과만 | 3, 5, 8, 15 | 25% |
| C2 재현성·실행 통제 | 같은 입력이면 같은 결과 | 14 | 15% |
| C3 투자조건 반영도 | 제외·상한·손실 감내 반영, 수정 가능 | 1, 2, 4, 10 | 25% |
| C4 성과 검증·과정 투명성 | 벤치마크 비교, 리포트, 단계 기록, 진행 상태 | 6, 7, 9, 11, 12 (+ C-12 언어) | 15% |
| C5 구현 완성도 | 요구 범위의 실제 구현·테스트 (보고서의 "구현 가능성"을 완성도로 읽음; 요구 13 제외) | 테스트 통과, 화면 범위 | 15% |
| C6 응답 속도·운영 비용 | 실행 시간과 LLM 비용이 예측 가능한가 | 측정값 | 5% |

총점 = Σ(그룹 평균 점수 × 가중치). 만점 5.00. 100점 환산 = 총점 / 5 × 100.

"보고서 기준"은 개념설계보고서 「다. 평가 내용」의 원문 요약. "우리 판정"은 무엇을 보고 5/3/1을 주는지.

> 라운드 5(2026-10-27) 부터 검증 체계가 바뀌었다: 최대낙폭(R1)은 합격 기준이 아니라 **표시(flag)** 규칙이고, 추천은 항상 하나(순위: 목표수익 → 비교지수 → 허용 낙폭 초과 폭 → Sharpe) 다. 결론 라벨은 `추천` / `추천(주의: …)` / `구성 불충분`. 현금 혼합안 대신 **낙폭 맞춤안**(`dd_match_*`, 실제 리밸런싱 일정으로 맞춘 정식 후보)이 비교표에 들어간다. 요구 5·6 의 "추천 없음" 판독은 "주의 라벨이 사실과 맞는가" 로 읽는다.

## 5. 도구와 파일

- 실행: `python -m backend.analysis.eval.run_scenarios --files <시나리오 JSON들> --answer all --llm api --out docs/mvp/grading/<날짜>` (프로필은 실행 뒤 자동 복원, 시나리오의 `horizon.start_date` 는 이번 요청의 기준일로 전달, `trading_currency: KRW` 는 USD 로 정규화하고 기록).
- 자동 지표: `python -m backend.analysis.eval.grade --from docs/mvp/grading/<날짜>` → `metrics.json` + 시나리오별 markdown 뼈대(사람 판독 칸은 비어 있음; 이미 채운 파일은 덮어쓰지 않음).
- 결정론: `python -m backend.analysis.eval.grade --compare <run_a> <run_b>`.
- 자동 점검표(기존): `python -m backend.analysis.eval.requirements` → `docs/mvp/requirements_check.md`.
