# Module7. 사용자 화면과 서비스 연동

전체 구조: [Module_prototype_v2.md](Module_prototype_v2.md)

## 1. 역할

이 모듈은 사용자가 프로필을 설정하고 투자 아이디어를 분석한 뒤, 리포트와 모의투자 결과를 확인하는 PC용 React 화면을 제공한다. 백엔드가 계산한 결과를 이해하기 쉬운 문장과 표·차트로 보여 준다.

화면에서 금융 지표나 비중을 다시 계산하지 않는다. API 응답을 표시하고 형식과 반올림만 처리한다. 요청 초안과 열린 패널 같은 임시 상태는 브라우저에 둘 수 있지만, 확정 조건과 결과의 원천은 백엔드의 DB·로컬 저장소다.

## 2. 화면 구성과 사용자 동선

고정 사이드바의 목적지는 홈, 투자 프로필, 분석 리포트와 모의투자다. 중앙에는 선택한 화면을 표시한다. 출처, 계산 상세와 조건 수정은 오른쪽 패널로 열고 닫을 때 원래 위치와 초점으로 돌아간다.

| 화면 | 주요 정보 | 다음 행동 |
| --- | --- | --- |
| 최초 프로필 설정 | 투자금·기간·성향·손실 기준, 간이 진단과 제약 | 저장 후 홈으로 이동 |
| 투자 프로필 | 저장 조건, 진단 성향·최종 성향과 버전 | 수정·검증·저장 |
| 홈 | 자연어 아이디어, 적용 프로필 요약과 이번 변경 | 요청 준비 |
| 보충 질문 | 부족·충돌·모호 항목 한 개 | 답변 후 다음 질문 또는 조건 확인 |
| 조건 확인 | 기본 조건·이번 값·변경 항목과 지원 제약 | 조건 수정 또는 분석 시작 |
| 분석 진행 | 대기 순번, 실제 단계 상태·요약, 오류와 취소 | 완료 후 리포트 확인 |
| 리포트 목록 | 전략명, 요청 요약, 분석 기준일·작성일·상태, 모의투자 여부 | 상세 조회 |
| 리포트 상세 | 일곱 섹션, 수치·근거·출처와 운용 조건 | 출처 확인·재분석·조건 수정·모의투자 |
| 수정 조건 확인 | 원안과 변경 초안, 반영 가능 여부 | 변경 확인 후 수정안 분석 |
| 비교 결과 | 조건·종목·비중·규칙과 같은 조건의 성과 차이 | 새 리포트 또는 새 모의투자 |
| 모의투자 시작 확인 | 기준 리포트·전략, 날짜·자본, 구성과 규칙 | 명시적 시작 |
| 모의투자 목록·상세 | 시작 이후 성과, 현재 구성, 운용 기록과 데이터 마감 | 새로고침·중지·재개·원본 리포트 |

분석 진행, 리포트와 모의투자 상세는 각 식별자 경로로 열 수 있게 한다. 새로고침과 재접속 시 백엔드에서 상태를 복원한다. 경로가 있다고 외부 공유 권한까지 제공되는 것은 아니며, 공유·접근 제어는 별도 정책이다.

## 3. 화면별 동작

### 프로필과 요청

프로필의 필수 네 항목을 채우기 전에는 저장할 수 없다. 코드 검증 오류는 해당 입력 옆에 이유를 보여 준다. 진단 성향과 최종 선택이 다르면 변경을 확인한다. 저장 후에는 이전 리포트에 적용된 조건이 유지된다고 안내한다.

홈에서는 저장된 기본 조건과 이번 요청의 변경분을 구분한다. 보충 질문은 한 번에 하나씩 최대 다섯 번 표시한다. 마지막 조건 확인에서 어떤 조건이 적용되는지 보여 주고, 분석 시작 버튼을 누른 뒤 대기열에 등록한다.

### 분석 진행

진행 단계는 실제 실행 순서대로 다음 다섯 묶음으로 표시한다.

1. 조건과 자료 확인
2. 후보 선정과 포트폴리오 구성
3. 백테스트
4. 사용자 조건 검증
5. 리포트 구성과 정합성 검사

이 순서는 원문의 화면 순서에서 백테스트와 조건 검증이 뒤바뀐 부분을 바로잡은 것이다. 진행률을 임의로 증가시키지 않고 `run_step`의 상태, 완료 요약과 시각을 사용한다. 대기 중이면 순번을 보여 준다. 취소 요청은 단계 경계에서 반영되므로 요청 후 바로 중단된 것처럼 표시하지 않는다.

브라우저를 닫아도 서버의 실행은 계속된다. 재접속 시 해당 run의 상태를 조회하며, 실패·중단한 실행을 자동 재개하지 않는다. 실패하면 단계와 사유, 가능한 다음 행동을 보여 준다. 경고를 포함해 끝난 결과와 실행 실패를 구분한다.

### 리포트

일곱 섹션은 [Module5.md](Module5.md)의 순서대로 한 페이지에 배치하고 이동 메뉴를 제공한다. 문단만 읽어도 핵심 판단을 이해할 수 있도록 구성하며, 패널에는 상세 계산과 출처를 넣는다.

표, KPI와 차트는 리포트 객체의 데이터셋을 참조한다. 번호 인용을 누르면 문서명, 발행기관, 발표일, 사용한 발췌, 연결된 주장과 원문 링크를 보여 준다. 현재 구성과 과거 평가 구성을 구분하고 날짜·가정을 함께 표시한다.

수치·인용 검증 실패로 제공이 차단된 문서는 상세 리포트로 열지 않고 사유를 안내한다. 반면 포트폴리오가 사용자 기준을 충족하지 못했다는 정상 분석 결과는 리포트에서 확인할 수 있다. 위험은 본문과 전제 섹션에서 설명하고 반복 경고 배너로 만들지 않는다.

### 수정과 비교

수정 패널에는 기준 전략·조건과 자연어 요청을 표시한다. 반환된 변경 초안을 원안과 비교하고, 지원할 수 없는 항목은 구분한다. 사용자가 변경 내용을 확인한 뒤 수정안 분석을 실행한다.

비교 결과에는 양쪽의 평가기간, 초기자본·적립, 비교지수와 리밸런싱 조건이 같다는 정보를 표시한다. 조건이 다르면 같은 기준의 비교처럼 보여 주지 않는다. 새 리포트와 새 모의투자는 별도 객체이며 원안을 덮어쓰지 않는다.

### 모의투자

시작 확인에는 실제 사용할 비중과 규칙을 보여 준다. 시작일에 재구성이 필요하면 재계산 결과를 반영해 다시 확인한다. 오늘 자료가 없으면 가능한 데이터 기준일을 안내한다.

상세에서는 시작 이후 성과와 과거 백테스트를 나누고, 시작·현재·목표·적용 비중을 구분한다. 적립 합계와 평가액 증가는 운용 수익률과 별도로 표시한다. 운용 기록, 갱신 주기와 마지막 성공 날짜를 제공하고 지연되면 새로고침을 지원한다.

중지·재개는 해당 상태와 기록을 반영한다. 시작일이 다른 모의투자를 단일 성과 순위로 비교하지 않는다. 갱신은 DB 자료를 기준으로 하므로 실시간 서비스라고 표현하지 않는다.

## 4. 백엔드 API 계약

실제 URL과 세부 응답 형식은 구현 시 확정한다. 프런트엔드는 아래 책임 단위로 API를 호출하고 DB나 결과 파일에 직접 접근하지 않는다.

| 책임 | 요청 | 응답 |
| --- | --- | --- |
| 프로필 조회·저장 | 프로필 입력 | 프로필과 버전, 검증 오류 |
| 요청 준비·질문 답변 | 아이디어, 이번 조건, 기준 리포트, 답변 | 다음 질문 또는 확인할 조건 |
| 실행·취소·상태 조회 | request_id 또는 run_id | 실행 상태, 단계 요약, 순번과 오류 |
| 리포트 목록·조회 | 필터 또는 report_id | 목록 또는 리포트 블록 문서 |
| 수정 요청·비교 조회 | 기준 리포트와 변경 요청 | 변경 초안 또는 비교 결과 |
| 모의투자 등록·조회·갱신 | 리포트·전략·시작 조건 또는 paper_id | 등록 객체, 평가와 리밸런싱 기록 |
| 모의투자 중지·재개 | paper_id와 상태 변경 | 갱신된 상태와 이력 |

실패 응답은 안정적인 오류 코드, 한국어 설명과 필요하면 필드별 오류를 포함한다. 성공 응답의 빈 수치와 실제 계산값 0을 구분한다. 사용자 확인과 서버 검증을 모두 적용하고 중복 시작·실행 요청 처리도 정의한다.

## 5. 문구와 숫자 표시

사용자 화면과 리포트는 한국어로 작성한다. 내부 개발 용어인 JSON·스키마·stub이나 데모·샘플·임시·추후 구현 같은 문구는 제품 화면에 노출하지 않는다. 개발자용 문서·로그와 사용자 문구는 분리한다.

판단은 자료와 계산의 범위 안에서 설명한다. 보장·확실한 수익처럼 단정하는 표현을 사용하지 않는다. 기능이 작동하지 않는 상태를 의미 없는 버튼이나 문구로 채우지 않고 실제 지원하는 행동을 표시한다.

| 값 | 표시 규칙 |
| --- | --- |
| 수익률·비율 | 백분율, 소수 둘째 자리 |
| 비중 | 백분율, 소수 첫째 자리 |
| Sharpe와 USD | 소수 둘째 자리 |
| KRW | 정수와 천 단위 쉼표 |
| 수익률 차이 | %p |
| 날짜 | YYYY-MM-DD |
| 환율 | 1 USD = X KRW와 환율 기준일 |
| 계산 불가 | 사유와 함께 표시; 0·무한대로 대체하지 않음 |

반올림은 표시 단계에서 ROUND_HALF_UP을 적용한다. DB·산출물의 원래 값은 유지한다. 반올림된 비중 표시 합계가 100%와 조금 달라도 원본 비중을 바꿔 맞추지 않는다.

## 6. 구현 상태와 완료 기준

원문에서는 화면과 서비스 API가 설계 단계다. 새 React 화면을 구현하며 기존 `Front/` 구현을 그대로 따라야 한다는 전제는 두지 않는다. 원문에 언급된 화면 문서는 `Front/docs/02-screens-and-flows.md`이지만 이 첨부에는 포함되지 않았으므로, 이 파일은 원문 명세에 제시된 흐름을 기준으로 작성했다.

프로토타입은 단일 사용자·인증 없는 구조다. 외부 공개 시 접근 제한과 라우트 공유 정책은 별도로 정해야 한다.

- 새로고침과 재접속 후 같은 요청·실행·리포트·모의투자가 열린다.
- 사용자 확인 전에는 본 분석과 모의투자가 시작되지 않는다.
- 실제 실행과 일치하는 상태를 표시하고 실패·지연 사유가 드러난다.
- 리포트의 일곱 섹션과 출처·계산 패널이 연결된다.
- 화면에 보이는 값이 백엔드 결과와 같고 표시만 반올림된다.
- 과거 성과와 현재 구성, 모의투자가 구분된다.
- 수정안의 확인·비교 흐름과 중지·재개 동작이 실제 API와 연결된다.
