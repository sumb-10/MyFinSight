# 프로젝트 개요와 범위

## 1. 서비스가 해결하는 문제

개인투자자는 뉴스와 기업 정보를 쉽게 찾을 수 있지만, 이를 자신의 투자금·기간·손실 감내 수준에 맞는 종목과 비중으로 연결하기 어렵다. 범용 LLM의 답변만으로는 근거 자료가 무엇인지, 실제로 실행 가능한 전략인지, 과거에 어느 정도의 손실을 경험했는지 확인하기도 어렵다.

MyFinSight는 사용자의 아이디어를 해석하고, 확인 가능한 정량·정성 자료를 이용해 투자 논리를 구성한 다음, 검증된 규칙으로 포트폴리오를 실행하고 백테스트한다. 사용자는 하나의 리포트에서 선정 이유, 비중 계산, 과거 성과와 위험을 이해하고 모의투자나 재분석을 선택할 수 있다.

서비스의 핵심 가치는 높은 수익률을 보여주는 데 있지 않다. 사용자가 자신의 아이디어가 어떤 전략으로 해석됐고, 그 전략의 판단 근거와 장단점이 무엇인지 이해하도록 돕는 데 있다.

## 2. 주요 사용자

주 사용자는 데스크톱 PC를 이용하며 투자 지식과 분석 시간이 부족한 개인투자자다. 관심 산업이나 기업은 알고 있지만 후보 비교, 비중 결정과 전략 검증을 혼자 수행하기 어렵다.

대표 시나리오는 다음과 같다. 사용자가 투자금 3,000만 원, 투자기간 3년, 손실 감내 수준 20%를 등록하고 “AI 성장에 투자하되 한 기업에 너무 집중하고 싶지 않다”고 입력한다. 시스템은 이미 저장된 정보를 다시 묻지 않고, 필요한 경우 집중 한도만 확인한다. 사용자는 적용 조건을 검토한 뒤 분석을 시작한다. 리포트에서 산업과 기업에 대한 근거, 구성 규칙, 과거 최대낙폭을 읽고 조건 수정 또는 모의투자 시작을 결정한다. 이 수치는 사용자 흐름 설명용이며 기본 프로필로 강제하지 않는다.

## 3. 핵심 기능

| 기능 | 사용자에게 제공하는 가치 |
| --- | --- |
| 투자 프로필 | 투자금·기간·성향·관심산업·제약조건의 반복 입력 감소 |
| 자연어 아이디어와 조건 확인 | 모호한 표현을 실제 분석 가능한 조건으로 구체화 |
| 데이터 기반 전략 구성 | 자료의 사실과 해석을 종목 선정·규칙에 연결 |
| 전략 검증과 백테스트 | 실행 가능성, 과거 성과와 위험 확인 |
| 통합 투자 리포트 | 상세한 분석·배분표·차트·근거를 함께 읽기 |
| 모의투자 | 선택한 전략의 추적 시작 이후 가상 성과 확인 |
| 수정안 비교 | 기존 전략과 변경안의 효과·불리한 점을 같은 조건에서 비교 |
| 실행 기록 | 실제 수행 단계와 성공·실패·사용 자료 확인 |

## 4. 두 개발 범위를 구분한다

| 항목 | 2026-10-02 백엔드 프로토타입 명세 | 이번 디자인·프론트엔드 목표 |
| --- | --- | --- |
| 입력 | 고정 Profile·Strategy Spec 파일 | 프로필 입력·수정, 자연어 아이디어, 조건 확인 |
| LLM | 사용하지 않음 | 향후 분석 연결을 수용하는 사용자 흐름과 자료 기반 리포트 구조 |
| 데이터 | 가격·환율·구성종목 수집과 품질 검사 | 정량 자료와 정성 리서치 기록을 연결한 화면 데이터 |
| 전략 | 사전 구현된 선정·비중·제약 규칙 | 신규 분석과 수정안 비교의 완전한 상호작용 |
| 결과 | 템플릿 근거를 포함한 텍스트 Report | 상세한 문단형 리포트, 차트, 출처 패널 |
| 모의투자 | 해당 프로토타입 범위 밖 | 명시적 시작 확인, 목록과 개별 상세, 원본 연결 |
| 실행 환경 | Python 분석 파이프라인 | React localhost 앱, 로컬 데이터 서비스와 저장 |

오른쪽 열은 구현 목표다. 프론트엔드에 화면이 있다는 이유로 실제 LLM 호출·데이터 조회·백그라운드 추적이 완료됐다고 판단하지 않는다. 로컬 고정 데이터를 사용하는 화면에서는 상호작용과 결과 연결을 먼저 완성하되, 실제 수행하지 않은 작업을 수행했다고 기록하지 않는다.

## 5. 투자 범위와 전략 원칙

- 현재 시장은 미국으로 고정한다. S&P 500·Nasdaq-100 관련 지원 Universe 안에서 구성한다. NASDAQ 전체 상장종목과 Nasdaq-100을 혼동하지 않는다.
- 주식 중심이며 ETF는 사용자 허용 조건과 구현 지원 여부를 함께 확인한다.
- 기본 전략은 매수 포지션만 사용하고, 총비중 100%로 전액 투자한다. 현금 배분·공매도·레버리지는 추가하지 않는다.
- 기본 운용 주기는 분기별 리밸런싱이다. 다른 주기는 실제 전략 엔진의 지원이 확인된 후 추가한다.
- 전략은 선정 규칙·비중 규칙·제약조건·리밸런싱·기간·비교지수·비용·자본·통화가 연결된 실행 명세로 관리한다.
- LLM이 임의로 생성한 코드를 실행하지 않는다. 검증된 명세를 사전 구현된 Strategy Library 함수에 연결한다.
- 후보와 수정안 비교에는 같은 기간·통화·비교지수·비용·무위험수익률을 적용한다.
- 후보가 조건을 충족하지 못하면 실패 사유를 설명한다. 제외 종목이나 최대 비중을 임의로 바꾸지 않는다.

## 6. 구현 범위에서 제외할 사항

- 실제 주문·자동매매·증권계좌 연결·사용자 자산의 보관 또는 이체.
- 미래 수익의 보장, 손실 한도를 보장하는 표현.
- 옵션·선물·가상자산 등 추가 자산군과 미지원 시장.
- 임의의 Python 코드 생성·실행으로 전략을 구현하는 방식.
- 과거 리포트·모의투자 이력을 새로운 프로필이나 수정안으로 덮어쓰기.
- 로그인, 클라우드 저장, 원격 동기화와 외부 애플리케이션 서버 의존.
- 모바일·태블릿 화면, 모바일 메뉴와 모바일 전용 재배치.
- 로컬 앱을 닫은 동안에도 프론트엔드가 계속 추적한다고 안내하는 기능.
- 서로 다른 시작일의 모의투자를 단순 수익률로 순위화하는 화면.

## 7. 기능 요구사항과 디자인 연결

| 요구사항 | 디자인에서 확인할 내용 |
| --- | --- |
| R1 프로필 관리 | 1개 프로필, 입력 검증, 저장·수정, 과거 결과 보존 |
| R2 아이디어 통합 | 저장 조건 활용, 부족·충돌 항목 질문, 이번 조건 확인 |
| R3 실제 자료 근거 | 자료명·발표일·기준일·관련 사실에 접근 가능 |
| R4 실행 가능한 전략 | 선정·비중·제약·리밸런싱 규칙 설명 |
| R5 검증 결과만 제공 | 비중·조건·수치 일치 검사, 실패 결과 차단 |
| R6 과거 평가 | 수익·위험·비교지수와 계산 조건 |
| R7·R8 리포트·근거 | 상세한 본문, 근거와 출처 연결 |
| R9 실행 기록 | 실제 단계별 상태와 결과 요약 |
| R10 수정 요청 | 기준 전략, 변경 확인, 별도 수정안·비교 결과 |
| R11 모의투자 | 명시적 활성화, 가상 성과와 추적 상태 |
| R12 진행 상태 | 디자인 흐름에 포함하되 백엔드 프로토타입의 완료 기능으로 간주하지 않음 |

R13 투자 요청 예시는 기존 요구사항에서 제외된 항목이다. 홈의 핵심 기능으로 새로 추가하지 않는다.
