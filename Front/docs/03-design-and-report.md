# 디자인과 투자 리포트 작성 기준

## 1. 디자인 방향

기존의 깨끗한 시각적 인상을 유지하되, 사용자가 아이디어를 입력하고 분석 결과를 충분히 읽을 수 있는 화면으로 개선한다. 홈은 분석 시작에 집중하고, 리포트는 전문가의 리서치 문서를 읽는 경험에 집중한다.

데스크톱 전용이다. 고정 사이드바, 읽기 편한 중앙 영역, 조건 입력의 2열 구성, 비교 표, 오른쪽 상세 패널과 일반적인 데스크톱 대화상자를 사용한다. 좁은 창에서는 최소 너비와 스크롤을 유지하며 모바일 메뉴나 카드 재배치로 바꾸지 않는다.

색·폰트·간격의 정확한 토큰은 기존 저장소를 확인한 후 결정한다. 문서 작성 단계에서 임의의 새로운 브랜드 시스템을 강제하지 않는다. 강조색은 주요 행동·선택 상태에 사용하고, 긍정·부정 수치를 색으로만 구분하지 않는다.

본문은 과도하게 넓어지지 않도록 읽기 너비와 줄 간격을 확보한다. 모든 문단을 별도 카드로 둘러싸지 않는다. 비교·배분 표는 넓은 공간을 사용하고, 필요한 경우 표 영역에 가로 스크롤을 둔다. 글자를 지나치게 줄이지 않는다.

## 2. 최종 사용자용 한국어

전체 UI는 자연스러운 한국어로 작성한다. 버튼은 행동을, 상태는 현재 사실을 짧게 전달한다. 분석 본문은 근거와 해석을 상세한 문단으로 쓴다.

| 사용 표현 | 피할 표현 |
| --- | --- |
| 투자성향 | 위험성향 등 동일 개념의 혼용 |
| 투자기간 | 정확한 투자기간 |
| 손실 감내 수준 | 손실 감수 선호 |
| 분석 기준일의 구성 | 포트폴리오 구성 snapshot |
| 배분 비중 | 화면마다 달라지는 배분·할당 용어 |
| 비교지수 | 설명 없이 반복되는 Benchmark |
| 분기별 리밸런싱 | 화면마다 달라지는 재조정 표현 |
| 투자 근거·과거 성과·모의투자 | 개발 단계 이름과 사용자 기능 이름의 혼용 |

모든 화면·패널·툴팁·빈 상태에서 `데모`, `샘플`, `mock fixture`, `임시 기능`, `추후 구현 예정`, `backend prototype`, `configured`, `화면 동작 검증용` 등 개발 설명을 제거한다. JSON·설정 파일·스키마·내부 결측 처리 용어도 일반 사용자 흐름에 남기지 않는다.

“표가 기준이고 도넛은 보조입니다”, “이 영역은 선정 이유와 비중 이유를 나눕니다”처럼 화면 설계 의도를 설명하는 문장은 삭제한다. 삭제한 문장마다 새 안내를 채우지 않는다. 사이드바에 저장 방식·동기화 부재 안내를 반복하지 않는다.

임시 표시 제거가 자료의 성격을 숨기는 일이 되어서는 안 된다. `모의투자`는 실제 제품 기능 이름이므로 유지한다. 합성 가격·가상 실험 자료는 참고자료·분석 조건에서 정확히 식별한다. 실제 공시나 시장 성과처럼 위장하지 않는다. 정상 화면의 개발 배너는 없애되 중요한 자료 출처와 결과 저장 상태는 유지한다.

## 3. 리포트의 핵심 원칙

리포트는 금융 리서치 전문가가 개인에게 모의투자 전략을 설명하는 문서처럼 작성한다. 주장, 확인한 사실, 해석과 투자 의미가 자연스럽게 이어져야 한다.

투자 판단은 다음 관계를 갖는다.

`DB 기록 → 확인 가능한 사실 → 분석적 해석 → 투자 의미 → 종목 선택·포트폴리오 결정`

LLM의 일반 지식이나 가격 변동성만으로 사업 경쟁력을 주장하지 않는다. 정성 DB의 자료가 부족하면 해당 주장을 줄이거나 생략한다. 기업을 선택한 논리와 정확한 비중 계산은 각각의 실제 근거에 연결한다.

본문은 구체적이고 균형 있게 쓴다. 자신감 있는 말투 자체를 전문성으로 취급하지 않는다. 모든 종목에 같은 문장을 반복하거나 지표의 교과서 정의로 해석을 대신하지 않는다.

## 4. 리포트 구조

상세 화면은 하나의 이어지는 페이지와 동작하는 섹션 이동 메뉴로 구성한다. 맨 위에 **한눈에 보기**(요약 대시보드)를 두고, 그 아래 일곱 부분을 접이식으로 둔다 (2026-10-25 라운드 4, 사용자 결정 R3).

한눈에 보기는 서버가 계산한 `summary` 를 그대로 그린다: 판단 카드(추천 여부·한 문장 결론·이유, 모의투자/조건 수정/재분석 버튼), KPI 타일(비교지수 값 동반, 값 없는 뷰 적중률은 숨김), 배분 비중(도넛 상위 8 + 기타 + 현금, 표), 누적 수익률 미니 차트(선택안·비교지수), 검증 요약(통과·주의·미통과 수와 미통과 규칙 이름), 다음에 할 수 있는 일. 섹션 안의 `kpis` 블록은 대시보드와 중복이라 그리지 않는다.

각 부분은 "접기/펼치기"가 있고 왼쪽 메뉴에 "모두 접기/펼치기"가 있다. 무거운 표는 `group_ko` 가 같은 연속 블록을 하나의 접이식 묶음(요청 조건 확인, 제외된 종목과 재선정 차이, 연도별·월별 수익률, 검증 상세, 자료 출처·계산 조건·실행 기록)으로 접고, 묶음 안 내용은 처음 펼칠 때 그린다. 25행이 넘는 표는 페이지로 나눈다. 리밸런싱 시점별 표·뷰 카드·체크포인트는 **리밸런싱 타임라인** 하나(점 스트립 + 선택 시점 상세, 보유·거래는 서버에서 지연 로딩, ←/→ 키)로, 선정 표 + 기업 카드는 **기업별 근거**(왼쪽 종목 내비 + 아코디언, 처음 3개 펼침)로, 규칙별 도넛 여러 개는 **비중 비교 표** 하나로 합친다. 주소에 `?sec=&company=&rb=` 를 남겨 새로고침해도 같은 자리로 돌아온다.

| 섹션 | 본문 내용 | 지원 정보 |
| --- | --- | --- |
| 종합 투자 판단 | 목적과 제약, 핵심 논리, 기업 역할, 중요한 선택의 대가, 과거 결과의 의미 | 전략명·기준일, 핵심 수익·위험 지표 |
| 산업과 시장 분석 | 수요·사업 구조·경쟁·수익화·공통 위험과 선택 기업의 관계 | 관련 DB 인용 |
| 기업별 투자 근거 | 회사별 사실·해석·선정 이유·보완 역할·반대 근거 | 문단 옆 출처 접근, 필요한 비교 자료 |
| 포트폴리오 구성과 운용 | 비중 계산, 상한·재배분, 중복 노출, 제약 반영, 리밸런싱 | 배분표·도넛·계산 상세 |
| 과거 성과와 해석 | 수익·비교지수·낙폭·회복·변동성·위험 조정 성과의 의미 | 성과·낙폭 차트, 동일 기간 지표 표 |
| 판단의 전제와 재검토 조건 | 논리를 지탱하는 가정, 약화 요인, 관찰할 정보 | 관련 기록과 실제 운용 조건 |
| 참고자료와 분석 조건 | 출처·기준일, 기간·통화·비용·환율·무위험수익률, 자료 한계 | 출처 패널, 적용 조건, 실행 기록 |

종합 판단은 자료가 뒷받침하는 3~5개의 충실한 문단, 기업별 분석은 보통 2~4개의 문단을 목표로 한다. 분량을 맞추려고 반복하지 않는다. 핵심 기업 분석은 패널을 열지 않아도 본문에서 읽을 수 있어야 한다.

## 5. 기업과 산업 분석

각 기업은 사업 구조와 해당 투자 아이디어의 연결에서 시작한다. 어떤 DB 자료를 확인했고, 그 사실이 사업 성장·수익성·경쟁력에 어떤 의미가 있는지 해석한다. 다른 보유 기업과의 역할 차이, 동일한 경제 요인에 노출되는 부분, 반대 근거를 함께 설명한다.

회사 역할이 다르다고 자동으로 위험이 분산됐다고 쓰지 않는다. AI 전략의 반도체·클라우드·인터넷 기업은 서로 다른 사업을 하면서도 같은 AI 투자 지출 사이클에 영향을 받을 수 있다. 이 판단도 실제 공급된 자료가 뒷받침하는 범위에서 설명한다.

매출·마진·시장점유율·설비투자·밸류에이션·경영진 전망을 서술하려면 관련 기록이 있어야 한다. 비교 후보에 대한 자료가 없다면 “다른 기업보다 우수하다”는 결론을 만들지 않는다.

## 6. 선정 근거와 비중 근거

기업 선정은 정성 자료·사용자 아이디어·실제 선정 규칙이 어떻게 작용했는지 설명한다. 기계적 규칙으로 선정한 기업에 뒤늦게 정성적 이야기를 붙여 “이 자료 때문에 선택했다”고 서술하지 않는다. 정성자료가 맥락 설명에만 쓰였다면 그 역할에 맞는 문장을 사용한다.

정확한 비중은 실제 수치 규칙을 설명한다. 역변동성 방식이면 측정 변동성, 한도 적용 전 비중, 개별·공통 상한, 상한 적용과 재배분, 최종 비중을 연결한다. 계산이 결정한 25%를 LLM이 직관적으로 결정했다고 설명하지 않는다.

분석 기준일의 구성이 역사적 전체 백테스트 기간에 고정되어 있었다고 오해하지 않도록, 기준일 배분과 과거 각 리밸런싱 구성을 구분한다. 전략 규칙·체결·비용을 자연스러운 언어로 설명하고 계산 상세는 보조 영역에서 확인한다.

## 7. 과거 성과 해석

누적수익률·CAGR·변동성·Sharpe·MDD·비교지수 차이를 함께 읽는다. 어떤 성과를 얻고 어떤 위험을 감수했는지, 사용자 목적에 어떤 의미가 있는지 설명한다.

기존 AI 리포트의 +121%와 비교지수 +139%를 유지한다면 차이는 −18.00%p다. 같은 기간의 다른 지표와 함께 이 열위를 설명한다. 이 수치를 새 결과의 고정값으로 복사하지 않는다.

차트에서 확인 가능한 강세·약세 구간, 최대낙폭의 고점·저점, 실제로 확인 가능한 회복 시점을 설명한다. 기간 안에 회복하지 못했다면 회복했다고 쓰지 않는다. 종목별 성과 기여 자료가 없으면 어떤 종목이 부진의 원인이라고 단정하지 않는다. 정성 뉴스가 가격 변화의 인과관계를 증명하는 것으로 취급하지 않는다.

사용자 손실 감내 수준보다 과거 MDD가 크다면 차이와 전략 검토의 의미를 관련 문단에 쓴다. 손실 감내 수준을 미래 손실 상한이나 자동 손절 조건으로 표현하지 않는다.

## 8. 위험과 재검토 조건

정상 리포트에는 노란 경고 배너, 경고 아이콘, 반복 주의 박스와 미구현 기능 안내를 두지 않는다. 투자 위험·반론·한계는 해당 분석 문단과 재검토 조건에서 설명한다.

“시장 변동성 증가 가능” 같은 포괄 문장 대신 어떤 사업 가정이 깨지면 기업 선정 논리가 약해지는지 설명한다. 전략에 없는 숫자 임계값·자동 매매 트리거를 만들어내지 않는다.

현재 구성종목을 과거에 적용한 백테스트라면 생존·선견 편향을 분석 조건에 명시한다. 과거 성과는 검증된 관측 결과로 표현하며 미래 성과의 보장으로 쓰지 않는다. 이러한 정보는 본문과 방법론에 자연스럽게 배치한다.

## 9. 출처 패널

주요 사실 옆에 작은 번호 인용을 둔다. 번호는 **읽는 순서**로 [1], [2]… 매긴다(근거 색인의 위치가 아니다). 인용을 열면 종류(뉴스·공시·재무 지표·계산값), 문서명, 발행기관, 발표일, 제공 가능한 짧은 발췌(없으면 "발췌 없음 — 헤드라인만 수집"처럼 이유), **이 근거를 인용한 문장**(섹션·블록 제목과 함께, 누르면 그 자리로 이동), 실제 원문 링크를 보여준다. 공시는 사건 종류(실적 발표·자사주 매입 결정 등)·양식·항목·접수일·이용 가능일을 보여 주고 "사건의 존재만 알려 준다"는 안내를 붙인다. DB 식별자는 선택적 보조 정보다.

근거 색인은 본문에 복사하지 않는다. 문서의 `evidence` 에는 본문이 인용한 근거만 들어 있고, 색인 전체는 **출처 드로어**(검색·종류·종목·기간 필터, 50건씩 페이지, 서버 `/reports/{id}/evidence`)로 본다. 서버 색인 조회가 안 되면 문서 안의 근거로 대신하고 그 사실을 표시한다. `evidence_ref` 블록("뉴스·공시 근거 N건 · 출처 보기")이 드로어를 그 블록이 인용한 근거로 걸러 연다.

기업의 사업 판단을 주가 시계열에만 연결하지 않는다. 정량 근거는 실제 입력값·기간·계산 조건을 표시한다. 값이라는 항목 아래 날짜 범위만 넣지 않는다. 존재하지 않는 제목·인용문·발표일·URL을 생성하지 않는다.

## 10. 접근성

- 충분한 대비와 눈에 보이는 키보드 초점을 제공한다.
- 모든 입력에는 라벨과 연결된 오류 메시지를 제공한다.
- 메뉴·버튼·패널·대화상자는 키보드로 조작할 수 있어야 한다.
- 대화상자와 패널에는 명확한 닫기 행동과 초점 복귀를 제공한다.
- 툴팁은 키보드로도 확인할 수 있게 한다. 핵심 사실을 hover에만 숨기지 않는다.
- 상태와 수치의 의미는 색 이외에 텍스트·부호로도 전달한다.
- 차트 데이터는 표나 접근 가능한 요약으로도 확인할 수 있게 한다. 모든 차트는 `ChartFrame` 안에 두어 제목·캡션(기간·단위·기준일·표본 여부)·"표로 보기" 전환·`role="img"` 라벨을 갖고, 화면에 들어올 때 그린다(높이 고정). 범주형 색은 검증된 8색(`lib/format.ts PALETTE`)이고 티커·시리즈는 어느 차트에서든 같은 색을 쓴다; 9개가 넘으면 "기타"로 묶는다.
