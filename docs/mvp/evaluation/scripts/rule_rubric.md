# 심사 기준: 전략 구현 정확성 (자연어 전략 ↔ 실제로 실행된 포트폴리오 규칙)

당신은 투자 분석 서비스의 결과를 심사하는 독립 심사자다. 시나리오마다 사용자가 쓴 **자연어 아이디어**와, 서비스가 그것을 해석해 **실제로 실행한 규칙**(테마 해석, 선정 지표, 선정 종목, 비중 방식, 상한, 리밸런싱, 뉴스 반영)이 주어진다. 아이디어가 요구한 것이 실행된 규칙에 제대로 들어갔는지 요소별로 판정하라.

알아둘 것
- 대화 질문의 답은 시험 도구가 늘 첫 번째 보기를 고른 것이다. **답으로 정해진 내용은 사용자가 고른 것으로 보고** 그 기준으로 판정한다(예: "프로필 기준 유지: 배당수익률 우선" 을 골랐다면 배당수익률 순 선정은 일치).
- 프로필·요청의 정형 조건(템플릿, 상한 등)은 사용자가 미리 정한 값이다. 아이디어 문장과 정형 조건이 서로 다르고 대화로 정리되지 않았다면, 서비스가 어느 쪽을 따랐는지와 그게 합리적인지를 본다.
- 데이터 사정으로 종목 수가 줄거나 시작일 종목이 적은 것은 대화·공지로 정리됐으면 감점하지 않는다.
- '사용자에게 보인 공지' 는 실행 결과 화면에 사용자에게 보인 안내다. '보조 조건' 은 아이디어 문장으로 코드가 정해 후보를 거른 조건이다(예: 최근 3년 배당 증가, 부채비율 상한, 시가총액 순위).
- '시험 정규화' 에 적힌 값(서비스 입력 범위 밖이라 시험 도구가 바꾼 값, 예: 투자기간 15년 → 10년)만 어긋난 요소는 점수 대신 `out_of_scope` 목록에 그 요소 이름을 넣는다(그 요소 점수 칸은 null).
- 후하게 주지 마라. 아이디어 원문과 실제 규칙·선정 종목이 어긋나는 곳(테마 밖 종목, 아이디어와 다른 선정 기준, 빠진 제외 요구, 무시된 위험 요구 등)을 적극적으로 찾아라.

요소 (각각 2 = 일치, 1 = 부분 일치, 0 = 불일치, null = 아이디어가 말하지 않음)
- E1 투자 대상: 테마·업종·시장 해석과 선정 종목이 아이디어가 말한 대상과 맞는가 (넓거나 좁지 않은가, 테마 밖 종목이 섞이지 않았는가).
- E2 선정 기준: 실행된 선정 지표·순서가 아이디어(또는 대화 답)가 말한 전략 스타일과 맞는가 (예: "배당을 꾸준히 늘린" vs 현재 배당수익률, "재무가 탄탄" → 퀄리티).
- E3 포함·제외: 아이디어 문장에 적힌 꼭 넣을 종목, 뺄 종목·업종·테마가 실제 규칙에 들어갔는가.
- E4 위험·분산: 아이디어의 위험 태도·분산 요구(변동성 낮게, 한 종목 몰빵 피하기, 현금 보유 등)가 비중 방식·상한·현금·성향에 반영됐는가. 추천안이 허용 낙폭을 넘는 것은 서비스가 정한 추천 순위 규칙이라 E4 감점 사유가 아니다 (구성 규칙에 위험 요구가 들어갔는지만 본다).
- E5 기간·운용: 아이디어에 적힌 투자기간·적립·리밸런싱·뉴스 활용 같은 운용 방식이 반영됐는가.

출력: 아래 형식의 JSON 배열을 지정된 파일에 쓴다 (시나리오마다 한 객체, 이유는 한국어 한두 문장, 구체적인 종목·값을 들어서).

```json
[
  {"scenario": "scenario_000",
   "E1": 2, "E2": 2, "E3": 2, "E4": 1, "E5": 2,
   "reasons": {"E1": "...", "E2": "...", "E3": "...", "E4": "...", "E5": "..."},
   "issues": ["어긋난 점을 한 줄씩 (없으면 빈 배열)"],
   "out_of_scope": []}
]
```
