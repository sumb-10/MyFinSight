# 데이터 현황 (운영 DB, 2026-10-17 기준)

운영 DB(Lightsail PostgreSQL)에 들어 있는 데이터를 한곳에 정리한 문서. 숫자는 2026-10-17 에 DB 를
직접 조회한 값이고, 매일 GitHub Actions 정기 수집으로 조금씩 늘어난다. 표는 모두
`python backend/scripts/coverage_report.py` (읽기 전용) 출력에서 옮겼고, 원문은 맨 아래 부록에 있다.
다시 뽑을 때는 같은 명령을 돌려 부록과 표를 바꾼다.
수집 규칙은 [수집작업.md](수집작업.md), 테이블 정의는 [DB_설계.md](DB_설계.md).

DB 전체 11GB. 큰 테이블: news 4.7GB, price_daily_source 3.2GB, price_daily 1.7GB,
valuation_daily 0.9GB, disclosures 0.4GB, financials_source 0.2GB (8절).

- 미국 2016년 전은 yfinance 하나뿐이라 모두 SINGLE (Alpaca 가 2016년부터).
- **한국 가격이 출처끼리 다른 이유**: 값이 틀린 게 아니라 과거 가격 보정 기준이 다르다. KIS 수정주가는
  유상증자·감자가 있으면 그 전 가격 전체에 보정 계수를 곱하고, yfinance 종가는 액면분할만 보정한다.
  예: 삼성SDI(006400) 는 KIS 종가 ÷ yfinance 종가가 2000~2024년 내내 0.9790, 2025년부터 1.0000
  (2025년 유상증자 전 가격을 KIS 만 2.1% 낮춤). 수준만 비교하던 때는 한국 MISMATCH 가 302,573 이었고,
  수익률 비교를 넣은 뒤 13,851 (1.4%) 로 줄었다. 남은 것은 보정이 바뀐 날(권리락 등)과 옛 yfinance 값이
  실제로 튄 날 (예: 2000~2001년 일부).
- 수익률·백테스트는 price_daily 를 그대로 쓰면 된다 (종목·칸마다 한 출처). 출처를 날짜마다 섞으면
  보정 기준 차이로 가짜 등락이 생긴다.
- 실패: yfinance WBD 1종목 (가격 없음). Alpaca 는 PSKY·WBD 가 최근 기간 데이터 없음.
- 미국 2016~ SINGLE 중 최근 하루치(약 520행)는 Alpaca 만 받은 날로, 토요일 주간 yfinance 갱신 뒤 검증된다.
- **한국 가격은 2026-10-16 까지 하루 늦게 들어왔다.** 수집이 시장과 상관없이 "UTC 어제"까지만 요청해서
  16:37 KST 한국 실행이 그날 종가를 받지 못하고 다음 평일 실행에서 받았다 (금요일 값은 월요일).
  2026-10-17 부터 시장마다 장 마감(+30분) 뒤면 그날까지 받는다 (collectors/prices/update.py `closed_through`).
  2026-10-16(금) 한국 값은 다음 한국 실행(10-19 월)이 증분 기간으로 채운다.

### PER·PBR 이 비는 이유

valuation_daily 는 그날까지 **공시된(disclosed_at ≤ 날짜)** 재무만 쓴다 (선견 금지). 비는 이유는 넷이다.

1. 적자: 순이익 TTM ≤ 0 이면 PER 은 비는 게 정상 (한국 2020~2025 행의 12~15%, 미국 5~11%).
2. 재무가 아직 없음: 한국 2004년 전은 재무가 없다 (KIS 연간 재무가 2004 사업연도부터). 미국은 SEC XBRL 이 2009년 의무화라, 2005~2008년 값은 2009~2010년
   XBRL 공시의 비교 연도로만 들어 있고 **그 공시일(filed)이 disclosed_at 이다.** 그래서 2007~2008년 기간 값도
   2009~2010년에야 "쓸 수 있는" 값이 되어 미국 PER 은 2010년 38% → 2011년 71% 로 시작한다.
3. **정정 공시로 공시일이 늦게 잡힘 (한국)**: DART 재무 API 는 보고서의 가장 최근 접수번호(정정본)를 주고,
   disclosed_at 은 그 접수일이다. 사업보고서의 13%(271/2,023)가 기간 끝에서 150일 넘게, 119건은 1년 넘게
   늦게 잡혀 있다 (6절 표). 예: 현대차 2018년 사업보고서 disclosed_at = 2022-02-17. 그동안 그 해 값을 못 써서
   순이익 TTM 이 통째로 빈다.
4. **연결(CFS) 값이 빠진 보고서 (한국)**: 보고서 7,176개 중 204개는 주요계정에 연결재무제표가 없고 별도(OFS)만
   있다. 분기값은 같은 연결구분 안에서만 이어 계산하므로 한 분기가 끊기면 그 뒤 4분기 TTM 이 빈다.
   예: 현대차 2018년 3분기(OFS 만) → 2018-09 분기 순이익 없음. 이제는 분기 사슬이 끊기면 사업보고서의
   연간 순이익("당기순이익(손실)", NI=FY)으로 PER 을 계산해 상당 부분 채운다 (한국 2017년 48% → 66%).

정한 것: disclosed_at 은 바꾸지 않는다. 최초 접수일로 당기면 정정 뒤 숫자를 그 전부터 쓰게 되어 선견 금지
제약에 어긋난다. 3·4번으로 빈 구간은 "그때 실제로 쓸 수 있는 값이 없었다"는 뜻이다.

## 8. 테이블 크기

DB 전체 11GB: news 4,684MB · price_daily_source 3,237MB · price_daily 1,656MB · valuation_daily 894MB ·
disclosures 381MB · financials_source 171MB · financials 91MB · fetch_log 37MB · 나머지 몇 MB.
테이블은 21개 = 코드의 18개 + 옮기기 전 실행 기록 보관 `run_artifact_v1`·`run_step_v1`·`report_v1` (모두 0행).
실행 기록 `run_artifact`·`run_step`·`report` 와 `extra_ticker` 도 아직 0행.
price_daily·price_daily_source 가 9.5GB 때보다 커진 것은 다시 채우기·교차검증으로 행을 고쳐 쓰면서 남은
이전 행 공간(PostgreSQL dead tuple)이다. autovacuum 이 다시 쓸 공간으로 돌리며, 파일 크기를 줄이려면
VACUUM FULL 이 필요하다 (표를 잠그므로 수집이 없는 시간에).

## 9. 남은 일·주의

- 보류: 생존 편향 (과거 편입·편출 이력과 상장폐지 종목 가격은 없음), 미국 2016년 전 가격 교차검증
  (Tiingo, 무료 한도), 한국 2004년 전 재무와 2015년 전 분기·배당·주식 수.
- DB 계정: 지금은 마스터 `myfinsight` 와 팀원 `reader` 뿐이다. 분석 모듈용 `myfinsight_read`·`myfinsight_write`
  (`backend/scripts/make_db_roles.py`)는 아직 만들지 않았다.
- 운영 DB 연결 끊김: 긴 백필 중 새벽에 두 번 끊겼다. 이제 저장소가 연결이 끊기면 5·20·60초 쉬었다가 같은
  트랜잭션을 다시 하고(backend/db/sql.py RECONNECT_WAITS), 백필 잠금도 끊긴 연결에서 풀다가 멈추지 않는다.
