# Module4. 포트폴리오 구성

전체 구조: [Module_prototype_v2.md](Module_prototype_v2.md)

## 1. 역할

이 모듈은 선정 종목에 얼마씩 배분할지 계산한다. 과거 수익률로 시장모형을 만들고 기준 비중을 계산한 뒤, 사용자가 원하면 DB 뉴스에서 만든 투자 의견을 Black–Litterman에 반영한다.

백테스트, 현재 구성과 모의투자가 같은 구성 함수를 사용하도록 구현한다. 날짜가 달라도 계산 방식은 같고, 그 날짜에 이용 가능한 자료와 근거만 달라진다.

## 2. 입력과 출력

| 구분 | 내용 |
| --- | --- |
| 입력 | 요청, 의도, 선정 종목과 전략 사양, 기준일별 가격·재무·환율·뉴스 |
| 출력 | 평가기간과 운용 조건, 시장모형, 기준 포트폴리오, 투자 의견, 목표 비중, 날짜별 비중 경로, 현재 구성 |
| 사용처 | Module5의 백테스트·리포트, Module6의 시작·리밸런싱 |

## 3. 날짜와 운용 조건 확정

분석 기준일은 DB에서 사용할 수 있는 최신 완료 거래일이다. 백테스트 기간은 기준일에서 `horizon.backtest_years`만큼 거슬러 올라가며 기본은 3년이다. 데이터 범위보다 이른 시작일은 자료 시작일로 조정하고 그 사유를 기록한다.

백테스트 시작일에는 Module3의 후보 검색과 정량 선정을 당시 기준으로 다시 수행한다. 사용자 테마는 유지하되, 당시 구성종목과 공개된 자료를 적용한다. 현재 선정과 달라진 종목을 기록한다. 분류 결과를 재사용할 수 있는 범위는 [Module3.md](Module3.md)의 과거 선정 조건을 따른다.

초기자본과 월 적립은 기존 정책대로 백테스트 시작일 환율로 USD 환산한다. 현재 배분 금액은 분석 기준일 환율을 사용한다. 각각 환율 값·날짜·출처를 따로 기록한다. 비교지수는 요청에서 정한 것을 사용한다.

리밸런싱은 `count`와 `unit`으로 정한다. `2w`는 10거래일 × count 간격, `1m`·`1q`·`6m`·`1y`는 지정한 달력 기간의 첫 거래일이다. 백테스트 마지막 날에는 별도 리밸런싱을 하지 않는다. count가 0이면 주기를 계산할 수 없으므로 미실행을 뜻하는지 확정해야 한다.

## 4. 기준 비중 계산

### 시장모형 추정

기준일 이전 최대 756거래일의 일수익률을 사용한다. 이 창 안에 252개 미만의 수익률만 있는 종목은 제외하고 기록한다. 제외 후 종목 수나 필수 포함 조건을 다시 검사한다.

공분산은 Ledoit–Wolf 수축 방식으로 추정하고 변동성과 상관행렬을 함께 저장한다. 아래 기대수익률·투자 의견은 연율이므로, 계산에 사용하는 Σ도 연율로 맞춘다. 일별 공분산과 연율 공분산을 혼용하지 않는다.

시가총액 비중은 기준일에 이용 가능한 발행주식수와 종가로 근사한다. 비교지수의 같은 추정 창에서 초과수익 평균을 분산으로 나누어 위험회피 계수 δ를 추정하고 사용자 성향 배수를 적용한다. 무위험수익률은 설정 상수다. δ의 범위·예외 처리와 수익률 단위는 기존 코드와 설정을 확인해 고정한다.

내재 기대수익률은 다음과 같이 계산한다.

\[\pi = \delta\Sigma w_{\mathrm{prior}}\]

여기서 `w_prior`가 시가총액 비중인지 사용자가 선택한 기준 비중인지 원문만으로는 확정되지 않는다. 아래 최적화에서 의견이 없을 때 기준 비중을 그대로 쓰는 정책과 일치하도록 확인해야 한다. 결과에는 실제 사용한 prior 비중을 저장한다.

### 네 가지 비중 방식

| 방식 | 계산 원리 |
| --- | --- |
| 동일비중 | 모든 종목에 같은 비중 |
| 시가총액비중 | 시가총액에 비례 |
| 역변동성 | 변동성의 역수에 비례 |
| 최소분산 | 제약 안에서 포트폴리오 분산 최소화 |

사용자의 `baseline_weighting`이 기준 포트폴리오다. 네 방식을 함께 계산해 이후 비교에 사용한다. 공통 제약은 비중 합 1, 종목별 최소 1%, 종목 상한과 섹터 상한이다. 섹터 상한이 1이면 추가 섹터 제약은 생략한다.

상한을 넘은 비중은 반복 재배분하고 결과를 다시 검사한다. 반복 횟수 내에 제약을 만족하지 못하면 성공으로 반환하지 않는다. 최소비중과 상한, 종목 수를 함께 고려해 구성 가능성을 확인한다.

결과에는 제약 적용 전후 비중, 변동성, 섹터 비중, 기대수익률, 예상 변동성·Sharpe와 유효 종목 수를 저장한다. 예상 통계와 실제 백테스트 성과는 구분한다.

## 5. 뉴스 기반 투자 의견

`use_news_tilt`가 꺼져 있으면 뉴스 의견 생성과 BL 조정을 생략한다. 켜져 있으면 구성 날짜 d의 직전 14일인 `[d−14일, d)`에서 DB 근거를 조회한다. 기본 최대 건수는 종목당 10건이다. 충분한 종목에 뉴스가 있는지 설정 기준으로 판단한다.

LLM에는 종목명·섹터·연변동성·내재 기대수익률·기준 비중, 사용자 테마와 뉴스 근거를 전달한다. 응답은 시나리오별 투자 의견 묶음이다.

| 필드 | 의미 |
| --- | --- |
| `scenario_id`, `title_ko`, `narrative_ko` | 시나리오 식별자와 설명 |
| `type` | absolute 또는 relative |
| `long`, `short` | 의견 대상 종목 또는 바스켓; 절대 의견에는 short 없음 |
| 기대수익률 값 | 절대 연 기대수익률 또는 두 바스켓의 연 기대수익률 차이 |
| `confidence`, `horizon_months` | 신뢰도와 의견 기간 |
| `rationale_ko`, `evidence_type`, `evidence_ids` | 판단 이유와 DB 뉴스 근거 |

이 수익률과 신뢰도는 LLM이 제안하는 모델 가설이다. 기사에 실린 사실이나 과거에 관측된 성과로 설명하지 않는다. 의견 기간과 연율 값의 관계도 모델에 일관되게 적용해야 한다.

코드는 유니버스 밖 종목, 중복 의견과 존재하지 않는 근거를 제거한다. 상대 의견의 양쪽에 같은 종목을 넣을 수 없고, 절대 의견에는 실제 뉴스 근거가 있어야 한다. 기대수익률과 신뢰도는 설정 범위로 제한하고 적용 전후 값을 기록한다. 신뢰도 상한은 `news_tilt.max_view_confidence`다. 근거 한 건으로 만든 의견은 신뢰도 0.3 이하로 제한한다. 신뢰도는 Ω 계산이 가능하도록 0과 1의 경계 처리도 정해야 한다.

뉴스가 충분하지 않거나 유효 의견이 모두 없어지면 기준 비중을 사용하고 `fallback`을 기록한다. LLM 기억으로 대체 의견을 만들거나 웹 검색으로 보충하지 않는다. 정보가 적은 일정 공지나 서로 반대되는 기사에 대한 처리는 프롬프트에서 지시하며, 실제 효과는 평가가 필요하다.

## 6. Black–Litterman 비중 계산

검증된 의견을 행렬 P와 벡터 Q로 바꾼다. 절대 의견은 특정 종목의 기대수익률을, 상대 의견은 long 바스켓과 short 바스켓의 기대수익률 차이를 표현한다. 바스켓 내부 가중치가 필요하면 생성·정규화 규칙을 고정한다.

기존 설계의 신뢰도 변환식은 다음과 같다. 의견 간 오차 상관은 반영하지 않고 Ω를 대각행렬로 둔다.

\[\Omega_{kk} = \left(\frac{1}{c_k}-1\right)p_k(\tau\Sigma)p_k^\top\]

이 문서에서는 공식 자체로 규칙을 정의한다. 원문에 붙은 방식 명칭은 구현 및 출처 확인 전 확정하지 않는다. c가 커질수록 의견의 불확실성이 작아진다. τ는 설정값이다.

사후 기대수익률은 다음과 같이 계산한다.

\[\mu_{BL}=\pi+\tau\Sigma P^\top(P\tau\Sigma P^\top+\Omega)^{-1}(Q-P\pi)\]

구현에서는 명시적인 역행렬보다 선형방정식 풀이를 사용하고 수치 실패를 검사한다. 비중은 SLSQP로 다음 목적함수를 최적화한다.

\[\max_w\;\mu_{BL}^\top w-\frac{\delta}{2}w^\top\Sigma w\]

제약은 비중 합 1, 종목별 최소 1%, 종목·섹터 상한, 기준 비중 대비 종목별 최대 조정폭인 `news_tilt.max_tilt_per_stock`이다. 최적화 성공 여부와 별도로 실제 비중이 제약을 만족하는지 검사한다. 의견 방향과 비중 변화가 제약 때문에 다를 수 있으므로, 방향이 항상 일치해야 한다는 검증 대신 조정 이유와 활성 제약을 기록한다.

의견이 없으면 최적화를 다시 풀지 않고 기준 비중을 직접 반환한다. 유효 의견이 모두 제거된 시나리오도 같은 정책을 적용한다. 뉴스 부족 시 기준 비중을 사용하는 기존 결정을 명확히 하기 위한 처리다.

기본 구성은 롱 온리·전액 주식이며 레버리지와 공매도는 없다. 현금 혼합은 Module5의 별도 대안이다. 사용자 입력 `min_cash_ratio > 0`을 기본 구성에서 지원하는지는 아직 확정되지 않았다.

## 7. 공통 구성 함수와 호출 위치

수학 계산은 `portfolio.py`에 두고 다음 함수로 묶는다.

```python
construct(tickers, as_of, req, intent, settings)
# templates, bl_portfolios, views, evidence_summary, warnings 반환
```

이 함수 안에서 시장모형→기준 비중→뉴스 의견→BL을 처리한다. 종목 재선정은 함수 밖에서 수행한다.

| 호출 위치 | 종목과 날짜 | 결과 |
| --- | --- | --- |
| 백테스트 시작 | 시작일에 재선정한 종목, 시작일 | 고정 목표 비중과 시나리오 |
| 과거 리밸런싱 | 시작일 종목 유지, 각 리밸런싱일 | 날짜별 비중과 의견; BL 세트 1개 |
| 현재 구성 | 현재 선정 종목, 분석 기준일 | 현재 비중, 근거와 USD·KRW 배분액 |
| 모의투자 리밸런싱 | 모의투자 종목 유지, 해당 날짜 | 새 목표 비중과 운용 근거 |

고정 목표 포트폴리오는 시작일 목표 비중을 이후에도 복원한다. 날짜별 재구성 포트폴리오는 각 날짜에 모형과 의견을 다시 계산한다. 현재 구성은 백테스트 입력이 아니며, 별도의 현시점 구성으로 리포트와 모의투자에 사용한다.

## 9. 완료 기준과 확인 사항

- 비중과 섹터 합계, 최소비중, 상한과 조정폭을 모두 만족한다.
- 의견이 없으면 선택한 기준 비중을 그대로 반환한다.
- 모든 의견의 종목·근거가 실제 입력에 있고 근거 날짜가 구성일 이전이다.
- 네 호출 위치가 같은 함수와 설정을 사용한다.
- 리밸런싱 중 종목을 임의로 교체하지 않는다.
- 과거 목표, 날짜별 경로와 현재 구성을 별도로 저장한다.

미확정 항목은 prior 비중의 정의, 현금 요청 지원, count 0의 의미, 혼합 시장 시차와 체결 규칙이다. 특히 당일 종가로 모형을 추정하고 같은 종가로 거래하는 경우에는 당시 이용 가능성과 체결 가능성을 보장할 수 없으므로, 사용할 정보 마감과 체결 지연을 Module5·6과 함께 확정해야 한다.
