# MyFinSight 최종 보고서 (초안)

작성 2026-10-25 · 브랜치 `module_mock_up` · 검토용 초안입니다.

## 1. 과제 요약과 채택안

MyFinSight는 개인 투자자의 조건(자금·기간·성향·제약)과 말로 적은 투자 아이디어를 받아, 미국(S&P 500·NASDAQ-100)과 한국(KOSPI200) 종목으로 포트폴리오를 만들고, 과거 자료로 성과와 위험을 계산해 근거가 붙은 리포트로 보여 주는 서비스다. 실제 매매와 계좌 연결은 하지 않는다.

상세설계보고서는 세 가지 구현안 가운데 **3안 "단계 고정 파이프라인 + 전략 사양(Strategy Spec) + 역할 한정 LLM"** 을 채택했다. 이 안의 뜻은 다음과 같다.

- 분석은 늘 같은 순서의 단계(요청 확정 → 종목 선정 → 포트폴리오 구성 → 백테스트 → 조건 검증 → 리포트)로 돈다. 단계마다 입력·출력이 정해져 있고 파일로 남는다.
- 전략은 숫자와 규칙으로 적힌 사양(어떤 지표로 고르고, 어떤 기준 비중을 쓰고, 어떤 상한과 리밸런싱 규칙을 지키는지)이며, 이 사양으로만 계산한다.
- LLM(언어 모델)은 아이디어 해석, 부족한 조건 질문, 회사 분류, 뉴스에서 읽은 의견(뷰), 설명 문장만 맡는다. 종목을 직접 고르거나 계산에 쓰는 숫자를 만들지 않는다.

이번 라운드의 목표는 이 채택안을 일곱 모듈로 실제로 구현하고, 화면(React)까지 사용 가능한 수준으로 올리고, 내용과 동작을 보고서로 정리하는 것이었다. 2026-10-24 기준으로 일곱 모듈과 화면이 모두 동작하며, 실제 팀 DB와 실제 LLM으로 끝까지 실행했다.

## 2. 전체 구조

```
화면 (React, :5173) ──/api/v1──▶ 서비스 API (FastAPI, :8001)
                                     │  로컬 JSON 저장소 data/analysis_store (프로필·요청·질문·큐·모의투자·비교)
                                     ▼
                          분석 일꾼 (worker, 단일 프로세스, 선입선출)
                                     │  단계 01…14 (함수 호출, output/<run_id>/NN_*.json)
                                     ▼
                  Repository ──읽기──▶ 팀 PostgreSQL (가격·환율·재무·뉴스·구성종목)
                             ──쓰기──▶ 로컬 SQLite data/analysis_results.db (run_step·run_artifact·report)
```

- **서비스 API는 분석을 실행하지 않는다.** 사용자가 "분석 시작"을 누르면 큐(`runs.json`)에 넣고, 일꾼이 하나씩 꺼내 돈다. 진행 상태는 화면이 2~3초마다 물어본다. 일꾼은 파일 잠금과 DB 세션 잠금으로 한 개만 돈다.
- **외부 호출 0건.** 분석 코드는 Repository만 읽는다. 인터넷 검색·다른 사이트 호출은 없다. (실험 단계 `module_mockup`에 있던 웹 근거 수집은 제외했다.)
- **쓰기 위치.** 팀 DB는 읽기 계정만 쓰고, 실행 기록·결과·리포트는 로컬 SQLite에 쓴다(`ANALYSIS_RESULTS_DB`로 바꿀 수 있음). 프로필·요청·대화·모의투자·비교는 로컬 JSON이다.

## 3. 모듈별 구현

### 3.1 M1 사용자와 요청

- **프로필**은 하나이며 저장할 때마다 버전이 늘어난다. 옛 리포트는 그때의 프로필 버전을 가리키므로 프로필을 고쳐도 옛 결과는 바뀌지 않는다.
- **요청 조립**: 프로필 기본값 위에 이번 요청의 덮어쓰기(보충 답변으로 바뀐 값)를 얹고, 자유 입력 답변은 아이디어 뒤에 덧붙인다.
- **HARD 검증**은 코드가 한다(Pydantic + 교차 규칙: 최소 ≤ 목표 ≤ 최대 종목 수, 섹터 상한 ≥ 종목 상한, 종목 상한 × 목표 종목 수 ≥ 1 − 최소 현금 비율, 레버리지·공매도 금지 등). 오류가 있으면 LLM을 부르지 않고 바로 고칠 항목을 알려 준다.
- **파생값**: 기준일(두 시장이 모두 거래한 가장 가까운 날), 환율과 USD 환산 금액, 리밸런싱 규칙, 백테스트 창(기본 3년, 자료가 부족하면 줄이고 경고).
- **보충 질문 대화**(결정 D6): LLM이 의도를 해석하면서 "답이 전략을 바꿀 때만" 질문을 최대 3개 제안한다. 코드는 질문 가능한 필드(SOFT 필드·기본값 필드)에 있고, 아직 묻지 않았고, 선택지 값이 HARD 검증을 통과하는 것만 남겨 **한 번에 하나**만 묻는다. 선택지 답은 코드가 필드에 반영하고, 자유 입력은 아이디어에 덧붙여 다음 턴에 다시 해석한다. 기본 상한은 5회이며 넘으면 분석을 시작하지 않고 미확정 항목을 알려 준다. 확정은 두 번 눌러도 같은 실행 ID를 돌려준다.
- **수정 요청**(요구 R10): 리포트를 보고 말로 적은 요청("엔비디아는 빼 주세요", "종목 수를 10개로")을 LLM이 "어느 필드를 어떤 값으로"로 옮긴다. 코드는 바꿀 수 있는 필드만 받고, 백테스트 기간·투자금·적립·비교지수·리밸런싱·종목 범위는 **원안 값으로 고정**해 공정하게 비교할 수 있게 한다. 바꿀 수 없는 요청은 이유와 함께 돌려준다. 수정안은 같은 질문·확인 흐름을 거쳐 별도 실행이 된다.

### 3.2 M2 금융 데이터

- Repository에 분석용 읽기 메서드 6개를 추가했다(`backend/db/analysis_readers.py`): 가격 막대, 환율 구간, 기준일 가치평가(PER·PBR·ROE·배당·시가총액, 최대 10일 전 값), 구성종목 스냅샷, 뉴스 묶음(반개구간, 종목당 상한), 종목 마스터.
- `MarketDataView(as_of)`는 기준일보다 뒤의 자료 요청을 예외(`LookaheadError`)로 막는다. 추정(공분산·지표·뉴스)은 기준일 **전날까지**, 체결은 기준일 **종가**다(결정 D4).
- **두 시장 혼합 규칙**(결정 D3): 달력은 미국·한국 거래일의 합집합, 한 시장만 쉬는 날은 그 시장 종목의 직전 종가를 유지, 한국 가격은 그날 환율로 USD 환산, 계산 통화는 USD. 한국의 거래 가정(소수 주식 불가·거래세)은 반영하지 않고 리포트 「전제와 한계」에 적는다.
- **품질 판정**은 수집기와 같은 함수를 쓴다(커버리지 0.95 이상 통과, 1거래일 결측만 채움, 2일 이상 연속 결측은 제외). 필수 종목(비교지수·고정 종목)이 제외되면 실행이 멈춘다.
- 실제 DB로 돌리며 찾은 문제: 기준일이 한글날(10-09)처럼 한 시장의 휴장일이면 창 첫날에 "직전 종가"가 없어 한국 지수가 결측으로 판정됐다. 패널을 만들 때 시작 앞 2주 자료를 같이 읽어 채운 뒤 잘라내고, 기준일 자체도 두 시장이 모두 거래한 날로 옮기도록 고쳤다.

### 3.3 M3 종목 선정

1. **의도 해석(02)**: LLM이 아이디어를 테마(GICS 코드·키워드·예시 종목), 선정 템플릿, 위험 변수, 뉴스 반영 여부, 보충 질문으로 정리한다. 코드가 템플릿-지표 일치, 기준일, 종목 수, 허용 낙폭·목표수익·비교지수(HARD 필드)를 요청 값으로 강제한다.
2. **후보 검색(03)**: 종목 사전(DB의 assets·index_constituent·gics_taxonomy로 만든 파일)에서 GICS 코드·키워드로 후보를 모으고, 시가총액·거래대금·제외 목록으로 거른다.
3. **테마 분류(04)**: LLM이 후보마다 테마 해당 여부와 신뢰도를 매긴다. 기준 신뢰도 아래는 뺀다.
4. **정량 선정(05)**: 템플릿의 지표(모멘텀 = 12개월 수익률 − 최근 1개월, 저PER, 퀄리티 = ROE, 저변동성 = 60일 변동성, 고배당)로 순위를 매겨 목표 종목 수만큼 고른다. 같은 회사의 복수 주식(GOOG·GOOGL)은 하나로 본다. 섹터 상한 때문에 전액 배분이 불가능하면 경고를 남긴다.
5. **기업별 근거(06)**: LLM이 종목마다 두세 문단을 쓰되, 재무 숫자는 `[fin:…]`, 뉴스는 `[ev…]` 인용 ID를 달아야 한다.

### 3.4 M4 포트폴리오 구성

- **시장모형**: 기준일 전날까지 756거래일(3년) 수익률로 공분산을 추정한다(Ledoit-Wolf 수축). 위험회피계수 δ는 비교지수에서 시장 내재값을 구해 성향 배수(안정 1.5, 중립 1.0, 공격 0.7)를 곱하고, 하한 1.5·상한 8을 둔다. 하한을 둔 이유는 급락 구간이 창에 들어오면 δ가 지나치게 작아져 비중이 극단으로 가는 문제(MVP 결함 6) 때문이다.
- **템플릿 비중 4종**: 동일비중, 시가총액비중, 역변동성, 최소분산. 모두 종목 상한·섹터 상한·최소 비중(1%)을 지킨다. 상한 때문에 전액을 넣을 수 없으면 남는 몫을 현금으로 두고 사유를 기록한다(결정 K-cap).
- **뉴스 뷰**: 기준일 직전 14일의 DB 뉴스(영어·한국어)만 근거로 LLM이 절대 뷰("A는 연 +15%")와 상대 뷰("A가 B보다 +5%")를 만든다. 뷰마다 근거 뉴스 ID가 있어야 하고, 수익률은 설정 범위로 잘라낸다. 뉴스가 있는 종목이 3개 미만이면 뷰를 만들지 않고 기준 비중을 쓴다(결정 K6).
- **Black-Litterman**(아래 4장)으로 기준 비중과 뷰를 결합하고, 효용 최대화로 비중을 구한다. 종목별 기울기는 `max_tilt_per_stock` 안에 묶는다. 최적화가 실패하면 뷰를 반영하지 않고 기준 비중을 그대로 쓴다(값을 지어내지 않음).
- **공통 함수 `construct()`** 하나를 네 곳에서 부른다: 백테스트 시작일, 리밸런싱일마다(종목은 유지, 비중만 갱신 — 결정 K8), 현재 구성(기준일), 모의투자.

### 3.5 M5 백테스트·검증·리포트

- **백테스트**(bt 라이브러리): 초기자본은 창 시작일 환율로 USD 환산, 월 적립은 적립일의 첫 거래일에, 리밸런싱은 기간 첫 거래일에, 수수료는 거래대금의 0.05%, 소수 주식 허용. 포트폴리오 10~14개(템플릿 4 + BL n, 각각 고정 비중과 리밸런싱일 재구성 두 방식)와 비교지수(SPY, QQQ, 한국 비중이 있으면 KODEX 200)를 같은 조건으로 돈다.
- **지표**: 기간 수익률, CAGR, 연 변동성, 최대 낙폭(MDD)과 회복 기간, 샤프·소르티노, 비교지수 대비 초과 CAGR·베타·알파·추적오차·정보비율, 월별·연도별 수익률, 적립을 반영한 IRR, 체크포인트별 비중·거래·드리프트.
- **검증 규칙**: R1 최대낙폭 ≤ 허용(필수), R2 CAGR ≥ 목표(참고), R3 비교지수 대비 초과(참고), R4/R5 종목·섹터 상한(리밸런싱일 필수, 드리프트 참고), R6 종목 수(필수), R7 변동성 적합(참고), R8 기타. 필수 규칙을 모두 통과한 것 중 샤프가 가장 높은 포트폴리오를 추천한다(동률은 MDD가 작은 쪽). 통과한 것이 없으면 **현금 혼합안**(같은 종목 비중을 줄이고 나머지를 현금으로)을 선택안으로 두고 그 뜻을 본문에 적는다(결정 D5).
- **결과 통합(13)**: 요청·의도·선정·구성·백테스트·검증·원화 환산·출처·설정·LLM 사용량을 하나로 묶고, 모든 인용 ID의 색인(`evidence_index`)을 만든다. 숫자를 다시 계산하지 않는다.
- **리포트(14)**: 일곱 부분 — ① 종합 투자 판단 ② 산업과 시장 분석 ③ 기업별 투자 근거 ④ 포트폴리오 구성과 운용 ⑤ 과거 성과와 해석 ⑥ 전제와 재검토 조건 ⑦ 참고자료와 분석 조건. 수치 블록(KPI·표·차트)은 코드가 만들고, LLM은 사실 요약 → 해석 → 문단 순서로 세 번 불린다.
- **검증 게이트**: 문단의 모든 인용 `[ev…]`, `[fin:…]`, `[calc:…]`가 색인에 있어야 하고, 뉴스 인용은 보유 종목에 관한 것이고 기준일 이전이어야 한다. 일곱 부분이 모두 있어야 하고, "보장"·"확실한 수익" 같은 단정 표현이 없어야 한다(부정형 "보장하지 않습니다"와 "무위험수익률" 같은 전문 용어는 허용). 문단의 숫자는 결과값과 대조해 없는 숫자는 경고로 남긴다. 실패하면 LLM에 오류를 되먹여 한 번 다시 쓰고, 그래도 실패하면 리포트를 저장하지 않는다.
- **수정안 비교**: 원안과 수정안의 조건 차이, 추가·제외·유지 종목, 선택안 비중 차이, 규칙별 판정 차이, 성과표(같은 평가 조건일 때만), 표의 값으로 만든 "나은 점·불리한 점" 문장을 문서로 저장한다. LLM을 쓰지 않는다.

### 3.6 M6 모의투자

- **시작**: 리포트에서 전략(검증한 포트폴리오 중 하나)·시작일·가상 자본·월 적립을 고르면 시작 비중과 배분 금액을 먼저 보여 준다(미리보기). "이 조건으로 시작"을 누를 때 같은 계산을 다시 하므로 확인한 비중이 그대로 적용된다. 시작일은 두 시장이 모두 거래한 날, 자료 마감 이하, 리포트 기준일 이상이어야 한다. 시작일이 기준일보다 늦으면 그날 자료로 `construct()`를 다시 돌리고 리포트 비중과의 차이를 보여 준다.
- **갱신**: 마지막 평가일 다음 거래일부터 자료 마감까지 날짜순으로 "보유 평가 → 적립 → 리밸런싱 → 수수료 → 기록" 순서로 처리한다. 같은 날짜를 두 번 처리하지 않는다. 운용 수익률은 단위가격 방식(적립은 그날 단위가격으로 새 단위 발행)이라 납입금이 수익으로 잡히지 않고, 비교지수에도 같은 자본·적립을 넣어 비교한다.
- **지연·중지**: 필수 가격이 없으면 가짜 기록 없이 "자료 지연"으로 표시한다. 중지하면 평가를 멈추고 보유를 유지하며, 재개하면 중지 기간은 비워 두고 지나간 리밸런싱은 "건너뜀"으로 기록한다.
- 일꾼이 한가할 때 한 시간에 한 번 진행 중인 모의투자를 갱신하고, 화면의 "최신 자료로 갱신"으로도 갱신한다.

### 3.7 M7 화면

React 19 + Vite 8 + Tailwind 4 + Recharts. 해시 라우팅(`#/analysis/:id`, `#/runs/:id`, `#/reports/:id`, `#/paper/:id`, `#/comparisons/:id`)이라 새로고침·재접속 시 서버 상태로 복원된다. 화면은 서버가 준 라벨·값만 보여 주고 금융 수치를 다시 계산하지 않는다. 가짜 진행률·가짜 질문은 없다. 서버가 끊기면 "서버 연결 끊김" 배지가 뜬다. 오프라인 자료 모드(`VITE_DATA_MODE=fixture`)는 샘플 리포트 하나로 화면 흐름만 보여 주며 모의투자·수정 요청은 지원하지 않는다고 안내한다.

### 3.8 실행기·큐·API

- 단계 레지스트리(14단계, 다섯 묶음: 조건 확인 / 후보·구성 / 백테스트 / 검증 / 리포트). 러너가 단계마다 `run_step`(QUEUED → STARTED → SUCCESS/PARTIAL/FAILED/CANCELLED)을 쓴다. 예외가 나면 그 단계는 FAILED, 남은 단계는 CANCELLED. 취소는 단계 경계에서 처리한다.
- 큐는 `runs.json` + 파일 잠금. 죽은 일꾼의 실행은 다음 일꾼이 FAILED로 정리하고 자동으로 다시 돌리지 않는다.
- API(`/api/v1`): health, meta/options, profile, requests(answer/skip/confirm/cancel), runs(cancel), reports(results/rerun/revisions/comparison), comparisons, paper(preview/create/list/detail/refresh/stop/resume). 오류는 `{"error":{"code","message_ko","fields?","details?"}}` 한 가지 모양이다.

## 4. 이론 정리

### 4.1 Black-Litterman

기준 비중 \(w_{mkt}\)(템플릿 비중)와 공분산 \(\Sigma\)에서 내재 기대수익률을 구한다.

\[ \pi = \delta\,\Sigma\,w_{mkt} \]

뷰 \(k\)개는 \(P\)(종목 조합, 행 합이 절대 뷰는 1, 상대 뷰는 0), \(Q\)(기대수익률), 신뢰도 \(c_k\in(0,1)\)로 적는다. 뷰의 불확실성은 He-Litterman 방식으로 신뢰도에서 만든다.

\[ \Omega_{kk} = \left(\tfrac{1}{c_k} - 1\right) p_k^{\top}(\tau\Sigma)p_k \]

사후 기대수익률과 공분산은

\[ \mu = \left[(\tau\Sigma)^{-1} + P^{\top}\Omega^{-1}P\right]^{-1}\left[(\tau\Sigma)^{-1}\pi + P^{\top}\Omega^{-1}Q\right], \qquad \Sigma_{BL} = \Sigma + \left[(\tau\Sigma)^{-1} + P^{\top}\Omega^{-1}P\right]^{-1} \]

비중은 효용 \(w^{\top}\mu - \tfrac{\delta}{2}w^{\top}\Sigma_{BL}w\)를 최대화해 구하되, 합 = 투자 비율, 최소 비중 1%, 종목 상한, 섹터 상한, 기준 비중에서 \(\pm\)`max_tilt` 안이라는 제약을 둔다(SLSQP). 설정: \(\tau = 0.05\), \(\delta\) = 시장 내재값 × 성향 배수(하한 1.5, 상한 8), 신뢰도 하한 0.1, 절대 뷰 수익률 범위 −50%~+100%, 상대 뷰 0~50%.

### 4.2 성과·위험 지표

- 기간 수익률 \(R = V_T/V_0 - 1\), CAGR \(= (V_T/V_0)^{252/n} - 1\) (거래일 \(n\); 1년 미만은 참고값으로 표시)
- 연 변동성 \(= \sigma_{daily}\sqrt{252}\), 하방 편차는 무위험수익률(연 4%) 아래 수익률만으로 계산
- 최대 낙폭 \(= \min_t (V_t / \max_{s\le t} V_s - 1)\), 회복 기간은 고점 회복까지의 거래일
- 샤프 \(= (CAGR - r_f)/\sigma\), 소르티노 \(= (CAGR - r_f)/\sigma_{down}\)
- 비교지수 대비: 초과 CAGR, 베타·알파(일별 회귀), 추적오차, 정보비율, 상승·하락 포착률
- 적립이 있는 경우 돈의 흐름을 반영한 연 IRR(XIRR)과 순이익(최종 평가액 − 투입 원금)을 따로 보여 준다

### 5.4 검증 게이트가 잡은 것

- 실제 LLM 첫 실행에서 리포트 문단이 "미래 성과를 보장하지 않으며"처럼 **부정형**으로 "보장"을 써서 금지 표현 게이트에 걸려 리포트가 저장되지 않았다. 부정형은 허용하고 프롬프트에서 그 단어를 피하도록 고친 뒤 통과했다. 게이트가 의도대로 "검증 실패 결과는 내보내지 않음"을 지켰다는 뜻이기도 하다.
- LLM이 낸 허용 낙폭(`effective_max_drawdown`)이 요청 값과 달라질 수 있어, 허용 낙폭·목표수익·비교지수는 LLM 값 대신 코드가 요청에서 계산해 덮어쓴다.

## 5.5 라운드 4 (2026-10-25) 변경 요약

사용자가 직접 써 본 뒤 요청한 다섯 가지(경고 정리, 뉴스 외 정성 자료, 리포트 화면, DB 자료 연결, 병목)를 한 라운드로 처리했다. 상세 기록은 `docs/updates/2026-10-25_round4.md`.

- **경고**: 한 실행 172건(대부분 중복·영어 개발 문구) → 구조화 경고(user/info/debug). 화면과 리포트 §6에는 "행동이 필요한 것"만 한국어로, 단계의 "경고 있음"도 그때만. 나머지는 실행 기록 파일에 보존.
- **공시 사건을 근거로**: 팀 DB의 `disclosures`(미국 8-K 등 32.9만 건, 한국 DART 37.8만 건)를 뷰의 주 근거로 연결했다(45일 창, 이용 가능일 기준, 사건 종류 허용 목록, 공시만 근거인 뷰는 신뢰도 0.25 상한). 뉴스가 적은 과거 구간에서도 뷰를 만들 수 있게 됐고, 기업별 근거·시장 분석·근거 색인·검증 게이트까지 같은 ID(`dc*`)로 이어진다.
- **병렬 실행(결과 동일)**: 의존이 끝난 단계를 묶어 동시에, 리밸런싱일별 뷰·분류 배치·리포트 호출을 풀로. 체크포인트 요약 경량화. walk-forward 뷰 적중률 계산의 기준일 버그를 고쳤다(값이 바뀜).
- **리포트 문서 v2 + 화면**: 요약 대시보드(결론 한 문장·KPI·배분·검증·다음 행동) + 접이식 7부분, 근거는 인용된 것만 문서에 싣고 전체 색인은 드로어로(문서 크기 12MB → 1MB 안), 리밸런싱 타임라인, 기업별 근거 아코디언, 공시 출처 패널. 옛 리포트는 읽을 때 자동 변환.
- **검증 실행**: 같은 시나리오를 다시 돌려 AI 반도체 3년·분기 633→325초, 미국·한국 반도체 561→264초(각 LLM 비용 $0.06~0.08). 저PER 2010~2016(27회 리밸런싱) 393초. 뷰의 공시 인용은 최근 구간 약 40%, 2010년대 3%(모델이 헤드라인을 우선 고름 — 다음 과제). 테마 분류(04)가 달라지면 같은 요청도 종목·검증 결과가 크게 바뀐다는 점(LLM 분류 변동성)을 한계로 확인했다.

## 6. 한계와 재검토 조건

- **생존 편향**: 구성종목 스냅샷이 2026-10-04 하나라 과거 기준일의 유니버스에도 지금 구성종목을 쓴다. 과거 구간 성과가 실제보다 좋게 나올 수 있다. 리포트 「전제와 한계」에 자동으로 적힌다.
- **한국 거래 가정**: 소수 주식 불가·거래세·호가 단위를 반영하지 않았다. 환율은 그날 종가 하나다.
- **재무 자료 공백**: 한국 2004년 전, 미국 2009년 전 뉴스. 가치평가 지표(ROE·배당)는 최신일 기준 미국 92%·72%, 한국 99%·72% 종목에 있다. 없는 종목은 해당 템플릿에서 제외된다.
- **LLM 비결정성**: 같은 입력에는 캐시로 같은 답을 쓰지만, 프롬프트나 모델이 바뀌면 결과가 달라진다. 설정과 모델 이름은 결과 묶음에 기록된다.
- **모의투자 갱신 시점**: 서버가 꺼져 있으면 갱신되지 않는다. 다시 켜면 밀린 날짜를 순서대로 처리한다.
- **리밸런싱일이 한 시장 휴장일인 경우**: 그 시장 종목은 직전 종가로 체결한 것으로 본다(기준일처럼 옮기지는 않음).
- **수정안 비교 범위**: 평가 조건(기간·자본·적립·비교지수·리밸런싱·범위)을 바꾸는 요청은 비교 대상이 아니다. 새 분석으로 안내한다.

### 7.3 저장 객체

- 로컬 JSON(`data/analysis_store/`): `profile.json`(버전), `requests/<id>.json`(대화·질문·확정 요청·수정 초안), `runs.json`(큐), `paper/<id>/`(portfolio.json, snapshots.jsonl, rebalances.jsonl), `comparisons/<id>.json`.
- 결과 DB(`data/analysis_results.db`): `run_step`, `run_artifact`(결과 묶음·설정·LLM 사용량), `report`(리포트 문서).
- 실행 산출물(`output/<run_id>/`): 단계별 JSON 14개, 프롬프트·LLM 원문, `llm_usage.jsonl`.

### 7.4 프롬프트

`backend/analysis/prompts/`: 02_intent(의도·질문), 04_classify(테마 분류), 06_explain(기업 근거), 09_views_news(뉴스 뷰), 14a_interpret(사실 해석), 14b_narrate(문단), 14c_market(시장 분석), 15_revision(수정 요청 해석). 모두 JSON 출력, 코드 검증, 실패 시 1회 재시도.

### 7.5 비용

실제 LLM 실행 1회 ≈ 0.08달러(입력 25.6만 토큰, 출력 7.1만 토큰). 시나리오 7개 + 재실행 2회 ≈ 0.65달러. 같은 조건의 재실행은 캐시로 거의 무료.

### 7.6 테스트

`pytest backend/tests/analysis -q`: 55개(합성 sqlite + stub LLM, 네트워크 없음). `cd Front && pnpm test`: 9개. 전체 백엔드 `pytest backend/tests -q`: 수집기 테스트 3건은 이번 변경 전부터 실패(pandas 인덱스 형, newsapi 예산).
