# 목업 기능 실제 연결 B-3: 초기 투자금 0원 시작 (2026-11-10)

이슈 #14 묶음 B(투자조건 규칙)의 3번 「초기 투자금 0원 시작」을 실제 서버에 연결했다.
각 항목은 "무엇을 / 왜 / 어디를(파일) / 어떻게 확인했나"를 적는다.

## 1. 문제

- 목업은 처음 투자금 0원 + 매월 적립으로 투자조건을 저장할 수 있었지만(`proposed_rules.allow_zero_initial_amount`), 실제 서버는 `initial_amount > 0` 만 받았다.
  실제 모드에서는 「투자금은 0보다 커야 합니다」로 막혔다.
- 검증만 풀면 계산이 깨진다. 합성 자료로 0원 백테스트를 돌려 보니 엔진(bt)과 금액 지표(넣은 돈·IRR)는 정상이지만,
  시간가중 수익률 지수가 첫 적립 전 평가액 0 으로 나누어 NaN(38일)·-inf(222일)가 되어 11단계가 실패했다.
  모의투자도 「평가액 ÷ 초기 원금」에서 0 으로 나눴고, 리포트 배분 금액·예상 매수 주문은 「초기 투자금 × 비중」이라 모두 0 이었다.

## 2. 결정 (사용자)

- **첫 적립일부터 투자.** 0원이면 첫 매월 적립일에 처음 매수하고, 그 전 평가액은 0. 수익률 지수는 첫 적립일부터 움직이고, 넣은 원금 대비 손익·연 IRR 은 그대로.
- **0원이면 매월 적립금 필수.** 둘 다 0 이면 저장·분석 요청·모의투자를 거절한다.
- **리포트 금액은 첫 적립금 기준.** 배분 금액·예상 매수 주문을 매월 적립금으로 계산하고 「첫 적립금」이라고 밝힌다.

## 3. 수정

### 백엔드

- **검증** `schemas/request.py` `Capital.initial_amount` 를 `ge=0`, 0 이면 `monthly_contribution > 0` (오류 필드 `capital.monthly_contribution`,
  한국어 문구 「처음 투자금이 0원이면 매월 추가 투자금이 있어야 합니다」 — `m1_request/validate.py`). 저장 스키마 `profile.schema.json`·`paper_portfolio.schema.json` 도 0 허용.
- **`/meta/options`** `proposed_rules: {"allow_zero_initial_amount": true}` — 프런트가 이 값으로 0원 입력을 연다.
- **백테스트 지수** `m5_backtest_report/backtest_engine.py` `extract_raw`: 전날 평가액이 0 이면 그날 수익률 0 (지수 100 유지). 원금이 있을 때의 「첫날 = 기준점」과 같은 규칙이라
  첫 적립일이 기준점이 된다. 비교지수도 「동일 적립」으로 같은 엔진을 돌리므로 같은 날 출발한다. 평가액 0 인 날의 종목 비중(0÷0)은 0.
- **백테스트 명세** `m4_portfolio/spec.py`: 0원이면 적립을 빼지 않는다 (`include_contributions` 가 꺼져 있어도).
- **리포트** `report_blocks.py` `basis_amount`·`forward_basis`: 배분 금액의 기준 금액을 한 곳에서 — 원금이 있으면 초기 투자금, 0원이면 첫 적립금.
  백테스트 시작일 배분 표·기준일 배분 표·요약 카드(`summary.allocation`, 새 필드 `amount_basis_ko`)가 함께 쓴다. 요청 표 투자금 줄은 「0원 — 매월 적립으로 시작 (첫 적립일에 처음 매수)」,
  가정 문단은 「초기 투자금 0 USD (첫 적립일에 처음 매수하고, 수익률은 그날부터 계산)」. `executor/stages.py` 기준일 구성 배분도 같은 규칙.
- **예상 매수 주문** `execution_orders.py`: 요약 카드 금액(첫 적립금)으로 계산하고 안내 문장 앞에 「처음 투자금이 0원이라 첫 적립금(매월 적립금) 기준입니다.」.
- **모의투자** `m6_tracking/paper.py`: 0원 시작은 단위 가격 1.0 에서 출발(보유·현금 없음, 최초 기록 「처음 투자금 0원 — 첫 적립일에 처음 매수합니다」).
  비교지수 수익률의 출발 가격(`benchmark_start_px`)은 첫 적립일에 정한다 — 그 전에는 둘 다 0%. 미리보기 배분은 첫 적립금 기준(`allocation_basis_ko`). `POST /paper` 의 `initial_amount` 도 0 허용.

### 화면

- 0원 규칙 문구에서 「목업 규칙」·「목업 화면에서만 가능 — 지금 서버는 0보다 큰 금액만 받습니다」를 빼고, 첫 적립일 매수·수익률 계산 기준을 적었다
  (`profile/validate.ts`, `home/DetailConditions.tsx`, `profile/ProfileScreen.tsx` 의 입력 안내·「예상 투자 일정」).
- 리포트 카드 2: `amount_basis_ko` 가 있으면 「투자 기준금액 · 첫 적립금」으로 배분 계산 금액을 보여 주고, 요청 원문(0원)을 기준금액으로 쓰지 않는다. 예상 매수 주문의 합계 문장도 「= 첫 적립금 …」.
- 모의투자 시작 창: 초기자본 입력 최소 0, 0원이면 표 아래에 「초기자본이 0원이라 금액은 첫 적립금 기준이며, 첫 적립일에 처음 매수합니다」.

## 4. 알아 둘 것

- 연평균 수익률(CAGR)·변동성은 백테스트 전체 기간으로 계산하므로, 첫 적립 전(최대 한 달)의 수익 0 구간이 들어간다. 비교지수도 같은 구간이 있어 비교는 공정하다.
- 원금이 있는 기존 계산은 바뀌지 않는다 (평가액 0 인 날이 없으므로). 기존 테스트 전체로 확인.
- 대화형 초기 설정(1번)에는 1번 브랜치에 이 브랜치를 합친 뒤 「0원 · 매월 적립으로 시작」 보기를 넣었다 (`2026-11-10_profile_chat.md`).
