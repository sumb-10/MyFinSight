기준: MyFinSight 프로토타입 모듈 명세 & 분배 (최신본). 담당 A (M02-01 ~ M02-05).
팀원은 이 문서의 함수·스키마만 쓰면 됨. SQL·테이블명은 몰라도 됨 (C-10).

> price_daily, fx_daily, financials, news + fetch_log)을 읽기 계정으로 직접 읽고, run_artifact·run_step·report 만
> 쓰기 계정으로 씀. 테이블·칸 대응과 운영 DB 옮기는 순서는 `DB_설계.md` 0절. 아래 Repository 설명은 이 저장소 코드를

## 2. 팀원이 받는 것

### 2-1. PriceFrame (명세 0-4)

| 항목 | 내용 |
|---|---|
| 형태 | `pandas.DataFrame` |
| index | `DatetimeIndex`, tz 없음, 미국 거래일, 오름차순, 중복 없음, 이름 `date` |
| columns | 티커 (yfinance 표기, 예 `BRK-B`), 정렬됨 |
| 값 | float64 수정종가, 종목 통화 (미국 USD, 한국 KRW, 한 표에 한 통화). 계약 `price_daily` 값 = (종목, 날짜) 마다 우선순위 출처의 원본 값 (CONSENSUS 중앙값 아님) |
| 결측 | M02-03 전에는 NaN 있음. M02-03 통과본은 NaN 없음 |
| 같이 오는 것 | `PriceMeta(source, as_of, fetched_at, tickers, currency)` |

- 계약 검사 함수 있음 → 테스트에서 그대로 씀.
- M03 은 `as_of` 전 거래일까지 잘라서 씀 (C-06, look-ahead 금지).

### 2-2. 품질 판정 결과 (M02-03)

| 규칙 | 내용 |
|---|---|
| 커버리지 | 값 있는 거래일 / Benchmark 거래일. 0.95 이상 통과 (0.95 정확히 = 통과) |
| 채움 | 1거래일 연속 결측만 직전값으로 채움 → `FILLED` |
| 제외 | 커버리지 미달 또는 2일 이상 연속 결측 → `EXCLUDED` + 사유 |
| 필수 종목 제외 | Benchmark·Spec 고정 종목이 제외되면 `DATA_REQUIRED_MISSING` |
| 전부 제외 | `DATA_NO_USABLE_TICKER` |
| 출력 | `DataQualityReport` + 사용 가능 종목만 남은 PriceFrame |

- `DataQualityReport.excluded` (티커 → 사유) 는 Report 「한계」에 그대로 씀 (D).
- 판정 기준은 `AppConfig.data` 에서만 읽음 (coverage_threshold, max_fill_days).

### 2-3. 구성종목 (M02-05)

| 항목 | 내용 |
|---|---|
| 스키마 | `IndexConstituent(index_code, ticker, name, sector, industry, snapshot_date, source, fetched_at)` |
| 지수 | `IndexCode.SP500`, `IndexCode.NDX`, `IndexCode.KOSPI200` |
| 갱신 | 최신 스냅샷이 직전 정기 변경일(미국 3·6·9·12월 셋째 금요일, KOSPI200 6·12월)보다 오래되면 새로 받음 |
| 검사 | SP500 495~510행, NDX 98~105행, KOSPI200 195~205행 (계약 M2-01), 티커 중복 없음, sector·industry 비어 있지 않음 |
| 실패 시 | 저장 안 함, `fetch_log` 에 FAILED + 이유. 기존 스냅샷 유지 + 경고. 스냅샷 날짜를 Report 한계에 표시 |
| 티커 | `latest_constituents` 는 yfinance 표기(`005930.KS`, `BRK-B`). DB `index_constituent.ticker` 는 계약대로 미국 yfinance 표기, 한국 6자리 코드(`005930`) |
| 분류 | sector·industry 는 GICS 명칭 (K3, industry_map 과 맞춤) |
| 한계 | 정기 변경 사이 수시 편입·편출은 반영 안 함 |

### 2-4. 환율

- `FxRate(pair="USDKRW", date, rate, source, fetched_at)`, 출처 심볼 `KRW=X`. rate = 1 USD 당 KRW.
- DB `fx_daily` 키는 (pair, date): 날짜마다 한 값.
- 계산은 USD 로만 함. 한국 종목 KRW 가격은 거래일 환율로 USD 환산 (계약 C-05, 분석 쪽).
- `get_fx_on_or_before(d)` → 그 날짜 이하 가장 최근 환율. 없으면 `None`.

## 3. Repository (M02-04) 메서드

다른 모듈이 DB 를 만지는 유일한 통로. 구현체는 A 가 줌.

| 메서드 | 쓰는 사람 | 내용 |
|---|---|---|
| `get_prices(tickers, start, end)` | B, C | `(PriceFrame, PriceMeta)` |
| `covered_range(ticker)` | A | 저장된 기간 |
| `get_fx_on_or_before(d)` | C, D | 환율 |
| `latest_constituents(index)` | B | 지수별 최신 스냅샷 |
| `save_run_artifact(run_id, request_id, results, params, llm_usage=None)` / `get_run_artifact(run_id)` | D | 결과 통합 JSON·파라미터 스냅샷·LLM 사용량 (dict). 같은 run_id 면 바꿈 |
| `save_step(rec)` / `get_steps(run_id)` | D | 단계별 실행 기록 (`StepRecord`, status: QUEUED·STARTED·SUCCESS·PARTIAL·FAILED·CANCELLED) |
| `save_report(report_id, doc, strategy_name=, request_summary=, as_of=)` / `get_report(report_id)` | D | 리포트 문서(dict) 저장·조회. report_id = run_id, run_artifact 먼저. 이미 있으면 거부 (불변) |
| `upsert_prices`, `upsert_fx`, `save_constituents`, `log_fetch` | A | 수집 쪽 쓰기 |

- 값이 같은 행은 다시 쓰지 않음 (같은 데이터 두 번 upsert → 두 번째 0행).
- 오류: `RepositoryError` (`REPO_WRITE_FAILED`, `REPO_READ_FAILED`).

## 4. 오류 코드 (F2)

| 코드 | 예외 | 언제 |
|---|---|---|
| `DATA_SOURCE_UNAVAILABLE` | `DataSourceError` | 수집 어댑터 설정 오류 |
| `DATA_REQUIRED_MISSING` | `DataQualityError` | 필수 종목(Benchmark 등) 제외됨 |
| `DATA_NO_USABLE_TICKER` | `DataQualityError` | 쓸 종목 0개 |
| `REPO_WRITE_FAILED` / `REPO_READ_FAILED` | `RepositoryError` | DB 쓰기/읽기 실패 |

- 전부 `MyFinSightError` 하위. `code`, `recoverable`, `details` 있음 (C-09).
- 티커 몇 개 수집 실패는 예외 아님 → `RawPriceBatch.failed_tickers` 에 사유 기록, 품질 판정에서 제외 처리됨.

## 5. 공통 제약 중 F2 관련

| 제약 | F2 에서 의미 |
|---|---|
| C-02 | 모듈 사이는 M00-02 스키마만 주고받음. 예외는 PriceFrame (DataFrame) |
| C-04 | 가격·계산 USD. 원화는 `KRW=X` 환율로 표시만 |
| C-05 | `date` = 미국 동부 거래일, 시각(`fetched_at` 등) = UTC |
| C-06 | 리밸런싱일 t 에는 t-1 까지 데이터만 씀 |
| C-07 | 값 만들지 않음. 1거래일 직전값 채움만 허용 |
| C-10 | DB 는 Repository 로만. SQL 직접 작성 안 함 |
| C-11 | 테스트는 네트워크 없이. 가격·구성종목은 Fake 구현으로 |
| C-12 | `logging` 사용, `print` 안 씀 |

## 6. DB

| 용도 | 접속 | 비고 |
|---|---|---|
| 공용 데이터 | AWS Lightsail PostgreSQL (서울), `reader` 계정 | 읽기만. 접속 주소는 A 가 개인 메시지로 줌. 사용법: 팀원_DB_사용.md |
| 분석 모듈 | 같은 DB, `myfinsight_read` (계약 읽기 테이블만) · `myfinsight_write` (+ run_step·run_artifact·report 쓰기) | `backend/scripts/make_db_roles.py` 로 만듦. 2026-10-17 운영 DB 에는 아직 없음 (그때까지는 `reader` 로 읽고 쓰기는 로컬 SQLite) |
| 로컬 확인·테스트 | SQLite (`sqlite:///data/myfinsight.db` 또는 인메모리) | 같은 Repository 인터페이스 |

- 가격·환율·구성종목은 A 의 정기 수집(GitHub Actions)이 채움. 팀원 실행 시에는 대부분 저장소에서 바로 읽힘.
- `reader` 는 쓰기 불가 → 공용 DB 에 실행 기록·리포트를 남기려면 쓰기 계정(`myfinsight_write`)을 씀. 없으면 로컬 SQLite.
