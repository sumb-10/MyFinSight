# Codex 작업과 완료 기준

## 1. 작업을 시작할 때

1. `docs/README.md`와 작업 관련 문서를 읽는다.
2. 실제 저장소의 AGENTS.md, 실행 방법, 프레임워크·라우트·스타일·공유 모델을 확인한다.
3. 기존 화면을 실행해 해당 흐름과 데이터를 확인한다. 문서의 목표를 구현 완료 사실로 취급하지 않는다.
4. 문제의 원인이 문장·레이아웃인지, 데이터 모델·연결인지 구분한다.
5. 기존 구조를 활용해 변경하고, 수정 화면에 연결되는 사용자 흐름을 확인한다.
6. 새로 확정한 계약·정책과 남은 연결 이슈를 문서에 반영한다.

이번 문서는 요구사항과 설계 기준을 제공한다. 앱 저장소 연결, 실제 화면 수정·실행 검증은 다음 작업이다. 사용자가 디자인 변경만 요청하면 그 범위에 맞는 구현과 검증을 수행한다. 승인되지 않은 원격 배포나 실제 거래를 추가하지 않는다.

## 2. 개선 우선순위

| 순서 | 작업 | 이유 |
| --- | --- | --- |
| 1 | 리포트별 요청·자료·보유종목·시계열·날짜 분리 | 내용이 잘못 연결된 상태에서 문장만 개선하면 오류를 확대함 |
| 2 | 정성 자료·주장·결정 연결, 실제 비중 계산 연결 | 전문가 리포트의 핵심 근거 확보 |
| 3 | 상세 문단과 보고서 읽기 구조 | 짧은 카드 중심 분석을 충실한 본문으로 전환 |
| 4 | 전체 화면 문구·상태·패널 정리 | 임시 기능 안내와 개발 설명 제거 |
| 5 | 분석 확인·모의투자·수정 비교·로컬 저장 흐름 확인 | 화면 완성과 실제 상호작용을 연결 |

이 순서는 작업 계획의 기본값이다. 사용자의 다음 요청이 특정 화면을 지정하면 해당 범위부터 작업한다.

## 3. 기존 화면에서 전달받은 개선 과제

다음은 이전 대화의 화면 검토 결과다. 현재 구현 상태는 새 작업 시작 시 다시 확인한다.

- 정성 분석이 기업·산업 설명 대신 미지원 안내로 표시되었다.
- 기업 선정 근거가 사업 역할과 변동성 순위를 조합한 한 문장으로 반복되었다.
- 근거 패널에 가격 자료만 연결되어 정성 판단의 문서·발췌를 확인하기 어려웠다.
- 비중 설명은 역변동성·상한 적용이라는 규칙명에 머물렀다.
- 과거 성과 숫자에 비해 비교지수 열위·낙폭·사용자 목적에 대한 해석이 부족했다.
- 개발 용어·경고·화면 설계 설명이 본문보다 눈에 띄었다.
- 미국 대형주 안정성 전략이 헬스케어·소비재·금융 조건을 표시하면서 AI 전략과 같은 종목·본문·성과를 사용했다.
- 해당 리포트의 생성일 2025-01-31이 자료·구성 기준일 2025-02-28보다 빨랐다.

안정성 전략을 유지하면 그 목적과 산업에 맞는 자료·종목·규칙·성과를 별도로 구성한다. 제목이나 관심산업만 바꾸지 않는다. 과거 날짜에 나중 자료를 넣어 오류를 숨기지 않는다.

## 4. 문서 간 차이와 남은 결정

| 항목 | 이번 작업 기준 | 구현 시 확인할 사항 |
| --- | --- | --- |
| 여러 시장 구상 vs 최신 US 고정 | 미국 지원 Universe | 추가 시장은 별도 범위 결정 |
| 짧은 템플릿 리포트 vs 상세 정성 리포트 | 상세 문단과 근거 연결 | 실제 리서치 자료·생성 파이프라인 |
| 상단 주의 알림 vs 경고 제거 | 정상 투자 위험은 본문·방법론 | 실제 실패 상태는 유지 |
| 가격 중심 백엔드 vs 정성 DB | 화면 모델에 자료·주장 연결 | 정성 자료 수집·검증과 LLM 연결 여부 |
| 백엔드의 모의투자 미포함 vs 전체 화면 | 시작 확인·목록·상세 흐름 구현 목표 | 고정 자료 시뮬레이션과 실제 갱신 구분 |
| 프로필 범위와 평가 기준 | 실제 검증 계약 사용 | 제안 값·성향 진단·후보 평가 기준의 확정 |
| 기본 비용·무위험수익률·Universe 크기 | 실제 설정과 결과를 표시 | 명세의 기본값·팀 확인 항목을 임의 확정하지 않음 |
| 분석 직후만 추적 가능 | 과거 리포트는 재분석 후 시작 | 새로고침 이후 시작 자격과 중복 활성화 정책 |

규칙과 데이터가 아직 연결되지 않았을 때는 내부 작업 기록에 남긴다. 사용자 화면을 개발 공지로 채우거나 성공한 것으로 위장하지 않는다.

## 5. 사용자 흐름 완료 확인

> 상태(2026-10-24): 아래 흐름은 모두 화면과 서버에 구현되어 있고, 서버 쪽은 자동 테스트(`backend/tests/analysis`, 55개)와 실제 DB·실제 LLM 시나리오 실행으로 확인했다(`docs/mvp/scenario_runs/`, `docs/mvp/requirements_check.md`). 브라우저에서 사람이 직접 누르며 확인하는 인수 점검은 아직 하지 않았으므로 체크 표시는 비워 둔다.


- [ ] 최초 사용자: 프로필 설정 → 성향 진단 → 제약 → 저장 → 홈 → 아이디어 → 필요한 질문 → 조건 확인 → 분석 → 리포트.
- [ ] 재방문 사용자: 저장 조건을 불러오고 필요한 항목만 질문하며 이번 변경을 확인한다.
- [ ] 과거 리포트: 개별 결과를 조회하고 같은 조건 재분석으로 신규 결과를 만든다. 원본은 바뀌지 않는다.
- [ ] 모의투자: 신규 결과 → 명시적 시작 확인 → 목록 → 해당 상세 → 원본 리포트·백테스트.
- [ ] 수정: 기준 전략 → 수정 패널 → 변경 확인 → 분석 → 같은 조건 비교 → 신규 리포트 → 선택적 신규 추적.
- [ ] 실패: 입력 수정·조건 수정·명시적 재시도로 복구하며 결과와 입력을 필요한 범위에서 유지한다.
- [ ] 저장: 프로필·리포트·추적 생성 후 reload해 각각의 내용과 연결이 유지된다.

## 6. 디자인과 콘텐츠 완료 확인

- [ ] 모든 주요 페이지·패널·빈 상태·툴팁의 한국어가 자연스럽고 일관된다.
- [ ] 임시·샘플·개발 용어, 설계 의도 설명과 의미 없는 문장이 제거됐다.
- [ ] 리포트에는 종합 판단, 산업 분석, 서로 다른 기업 분석과 운용·성과·재검토 설명이 있다.
- [ ] 주요 판단의 정성 DB 근거를 열 수 있고 본문만 읽어도 핵심 분석을 이해할 수 있다.
- [ ] 정확한 비중은 실제 계산 규칙과 출력에 연결됐다.
- [ ] 표·차트·지표가 설명을 지원하며 정상 리포트가 경고 배너로 지배되지 않는다.
- [ ] 투자 위험과 불리한 결과를 생략하지 않는다. 운영 실패는 행동 가능한 상태로 표시된다.
- [ ] 데스크톱 리사이징·표 스크롤·키보드 조작·초점 복귀가 사용 가능하다.

## 7. 데이터와 구현 완료 확인

- [ ] 각 메뉴·리포트·추적 항목이 올바른 개별 데이터를 연다.
- [ ] 비중 합·상한·제외 조건·배분 금액·환율 계산이 일치한다.
- [ ] 시계열 끝값·수익률·MDD·본문 숫자가 같다.
- [ ] 비교지수와 원안·수정안의 기간·통화·계산 조건이 일치한다.
- [ ] 자료·작성·배분·추적 날짜가 일관되고 미래 관측값이 없다.
- [ ] 근거 제목·발표일·발췌·URL을 임의로 생성하지 않았다.
- [ ] 합성 수치를 실제 시장 성과나 공시처럼 표현하지 않았다.
- [ ] 프로필 변경·수정 분석·추적 시작이 과거 결과를 덮어쓰지 않는다.
- [ ] 미정 지표를 0이나 무한대로 대체하지 않는다.
- [ ] 고정 자료 모드는 인터넷·원격 서버 없이 localhost에서 정상 실행된다.
- [ ] 저장 실패·조회 실패·로컬 API 연결 실패를 실제 성공으로 처리하지 않는다.
- [ ] 앱 종료 중의 처리·갱신을 약속하지 않는다.
- [ ] 기존 프로젝트에 맞는 빌드·타입·검사와 변경 관련 흐름 확인을 통과했다.

## 8. 작업 결과 보고

Codex는 무엇을 바꿨는지, 사용자에게 어떤 차이가 생겼는지, 어떤 흐름을 확인했는지 간결히 보고한다. 연결되지 않은 정성 자료·실제 분석·추적 기능이 있다면 구체적으로 구분한다. 실행하지 않은 검증을 통과했다고 쓰지 않는다.

디자인 완료는 예쁜 첫 화면이나 정적인 카드 완성을 의미하지 않는다. 실제 버튼·패널·개별 데이터·상태·저장과 사용자 흐름이 함께 동작해야 한다.
