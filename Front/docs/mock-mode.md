# 목업 모드 (Mock mode) — 구조·계획·제안 계약

> 상태: **1~6단계 완료** (목업 모드 구조, 분석 리포트, 리포트·모의투자 이름, 내 투자조건·새 분석, 분석 진행·모의투자, 일반 모드 세 가지 기능·연동 명세). 이후 화면 다듬기도 반영되어 있다.
> 처음이라면 [README](../README.md)의 「목업 모드」부터 본다.
> 이 문서의 「제안 계약」은 **백엔드와 합의되지 않은 제안**이다. 지금 실제 서버는 이 값을 주지 않는다.

## 1. 목적

백엔드가 아직 주지 않는 데이터가 필요한 기능도 **디자인과 사용자 흐름을 먼저 확정**하기 위해, 실제 서버 대신 목업 자료로 동작하는 모드를 둔다.
목업 모드는 실제 서비스 기능이 아니며, 목업 결과는 실제 투자 분석 결과가 아니다.

## 2. 실행 방법

| 모드 | 주소 | 데이터 |
|---|---|---|
| 일반 모드 (기본) | `http://localhost:5173/#/home` | 실제 서버 (`/api/v1`) |
| 목업 모드 | `http://localhost:5173/?mock=1#/home` | `src/mocks` 의 목업 자료 |

- `?mock=1` 은 해시(`#/…`) 앞에 둔다. 해시 라우팅이라 화면을 옮겨도 `?mock=1` 이 유지된다.
- 화면 맨 위 노란 띠의 「일반 모드로 돌아가기」 또는 주소에서 `?mock=1` 을 빼면 일반 모드로 돌아간다.
- 오른쪽 아래 「목업 데이터」 버튼 → 시나리오 패널 (리포트·분석 진행 상태·해석 중/해석 실패/질문 중 요청·모의투자·투자조건 0원 전환·목업 데이터 초기화).
- **허용 환경:** 개발 서버(`pnpm dev`)에서만 켜진다. 운영 빌드(`pnpm build`)는 목업 코드가 번들에 들어가지 않으며 `?mock=1` 을 무시한다.
  예외로 빌드할 때 `VITE_ENABLE_MOCK=1` 을 명시하면 그 빌드에서는 허용된다 (시연용).

## 3. 일반 모드와의 분리

| 항목 | 방식 |
|---|---|
| 서비스 선택 | `main.tsx` 가 처음 한 번 고른다: 개발 환경 + `?mock=1` → `MockService`, 그 외 → 기존 `HttpService` |
| 네트워크 차단 | `MockService` 는 서버 요청 함수(`fetchJson`)를 쓰지 않는다. 추가로 `fetchJson` 은 목업 모드에서 `MOCK_NETWORK_BLOCKED` 오류를 내고 요청을 보내지 않는다 |
| 저장 분리 | 목업에서 바꾼 상태(이름·투자조건·모의투자·요청)는 이 탭의 `sessionStorage["myfinsight.mock.store.v1"]` 에만 둔다. 화면 상태 키도 목업은 `myfinsight.mock.ui.v1`, 일반은 기존 `myfinsight.ui.v1` |
| 운영 빌드 | `import.meta.env.DEV` 조건을 import 자리에 직접 써서, 운영 빌드에서 목업 코드(자료·서비스·패널)가 번들에서 제거된다 (빌드 산출물로 확인) |
| 새 기능 노출 | 제안 계약 메서드(`renameReport` 등)는 `AnalysisService` 에 **선택 메서드**로만 있다. 실제 `HttpService` 에는 없으므로 일반 모드 화면은 해당 기능을 열지 않는다 |
| 표시 | 목업 모드에서는 모든 화면 맨 위에 「목업 데이터 화면입니다 · 실제 투자 분석 결과가 아닙니다.」, 오른쪽 아래에 「목업 데이터」 버튼이 항상 보인다. 목업 문장·자료에는 `[목업]` 표시를 붙였다 |

| 홈에서 만든 새 요청 (`mock_req_NNN`) | 실제 서버처럼 번호를 먼저 돌려주고, 평소 지연의 50배(기본 6초) 동안 해석 중(`interpreting`)이다가 질문 중이 된다. 해석 중에는 지난 시간만큼 서버와 같은 6단계(조건 정리 → … → 질문 고르기)가 차례로 진행되고 결과 문구(테마·후보 42개·분류 1/2 묶음 등, 목업 값)가 붙는다. 목업 상태가 `sessionStorage` 에 있어 해석 중에 새로고침해도 이어진다. 재분석·수정 요청은 실제 서버처럼 해석까지 끝낸 뒤 돌려준다 | 테스트(지연 0)는 바로 질문 중 |

| 처음 사용자 | 패널 「처음 사용자 (투자조건 없음)」: 저장하기 전까지 투자조건 없음 → 앱을 열면 대화형 초기 설정(`#/profile/chat`) | 저장하면 버전 1 |

**일관성:** 리포트의 KPI·비교표·판단 이유·검증 문장·리밸런싱·요약 배분·매수 실행 예상·모의투자는 모두 같은 계산(`backtest.ts`)에서 나온다.
예) 판단 이유의 「SPY 대비 초과 CAGR」 = 검증 규칙 문장, 최종 평가금액 = 리밸런싱 마지막 시점, 기업 카드 비중 = 선택 전략 비중,
매수금 + 수수료 + 남는 현금 = 투자금(USD), 원화 = USD × 그날 환율. 테스트(`mocks.test.tsx`)가 이 관계를 확인한다.

**목업 계산의 단순화 (실제 백엔드와 다름):** 시세는 시드가 고정된 예시 값, 매일 같은 비중 유지, 휴장일 없음, 무결성 검사는 모두 통과,
「구성 불충분」은 선택안의 주식 비중 50% 미만으로 판단(백엔드는 기준 구성의 투자 비율로 판단).

## 6. 제안 계약 (초안) — `src/api/proposed.ts`

리포트 응답에 `proposed` 객체로 붙는 값 (목업만 채움):

| 필드 | 쓰임 (계획 단계) |
|---|---|
| `execution` | 종목별 예상 매수 주식 수(정수/소수점 구분)·매수 금액·수수료·남는 현금 (2단계) |
| `allocations.{current, recommended_now, backtest_start}` | 현재 구성 / 추천 전략을 기준일에 적용 / 백테스트 시작일 — 기준·날짜를 함께 (2단계) |
| `chosen_vs_baseline` | 선택 전략과 기준 비중의 종목별 비교 (2단계) |
| `company_views` | 종목별 뉴스 투자 의견 생성 여부 (생성 / 근거 부족 / 뉴스 반영 꺼짐) (2단계) |
| `request_log` | 처음 아이디어·질문과 답변·말로 보탠 요청(결과)·최종 조건 (2단계) |
| `krw` | 날짜별 환율·원화 평가액·리밸런싱 원화 금액 (2단계) |
| `market_topics` | 시장 주제 분류 카드 (2단계) |
| `company_reasons` | 기업 선정 이유 구조화 (2단계) |
| `risk_profile` | 분석 당시 5단계 성향(최종·자동 진단), 기본·적용 변동성 기준, 다른 이유, 참고로 바뀐 검사 (2단계) |
| `structured` | 판단 이유·검증 규칙·손실 감내·연 환산·투자 기준금액·원화 최종 평가금액·KPI 이름/기간·비교지수·리밸런싱 제목 정보·비교표 역할/ID·제외 사유 이름 (2단계) |
| `explanations` | 전략 설명·추천 순위 기준 전체·ETF 설명·짧은 기간 규칙·성향별 기본 변동성·추가 용어 (2단계) |

| 메서드 | 쓰임 |
|---|---|

| `getMessageResults` | 말로 보태기 결과 (반영됨/반영 안 됨/확인 필요, 바뀐 조건) (4단계) |
| `getRunWarnings` | 단계별 경고 전체 (같은 단계의 같은 문구는 count 로 묶음, 끝난 단계만) (5단계) |
| (실행 필드) `cancel` | `GET /runs/{id}` 에 붙는 취소 결과: 요청·완료 시각, 멈춘 단계, 완료 단계 수, `immediate` (5단계). 처음 이름은 `proposed_cancel`, 실제 서버 구현(2026-11-10) 때 정식 이름으로 |
| `getPaperKrw` | 모의투자 원화 성과: 날짜별 환율 상태(ok/carried/missing)·원화 평가액, 넣은 원금(원화), 원화 손익·수익률, 같은 방식의 USD 수익률, 환율 변화·효과, 상태별 일수, 계산 불가 사유 (5단계) |

필드별 상세 명세(타입·예시·기준 시점·백엔드가 할 일·연동 시 고칠 파일)는 7단계에서 이 문서에 추가한다.

- 말로 보태기는 목업 종목의 회사명·티커 + 「넣/포함/꼭」·「빼/제외/말고」만 알아듣는다. 종목만 있고 넣을지 뺄지 모르면, 또는 뺄 대상을 모르면 「추가 확인 필요」. 이미 들어 있는 종목이면 「반영되지 않음」.
- 필수 질문: 꼭 넣을 종목 질문만 선택, 나머지는 필수. 필수 질문을 비운 `answerBatch` 는 422 로 거절한다.
- 성향별 추천은 `mocks/data/strategy.ts` 의 미리 정한 표다 (실제 추천 규칙 아님).

**목업 계산 규칙:**
- 진행 재생: 대기 3초 → 단계마다 3초(진행 화면의 상태 확인 간격 2.5초보다 길게, 2026-11) → 완료(정상 추천 리포트로 연결) 또는 백테스트 단계에서 실패. 경고는 단계가 끝날 때 차례로 생긴다. 다시 실행은 새 진행 재생 실행을 만든다.
- 취소: 누른 시각에 진행을 멈추고 1.5초 동안 「취소 처리 중」. 끝난 분석은 409 로 거절한다. 완료된 단계는 「완료」로 남고 나머지는 「취소됨」.
- 원화 수익률 = 원화 평가액 ÷ 넣은 원금(원화) − 1. 원화 평가액 = 그날 USD 평가액 × 그날(또는 대체) 환율, 원화 납입은 납입한 원화 금액 그대로.
  USD 비교도 같은 방식(평가액 ÷ 넣은 원금 − 1)이라 차이는 환율 효과다. 적립이 없으면 (1+USD 수익률)×(1+환율 변화율)−1 과 같고, 적립이 있으면 납입마다 환율이 달라 단순 곱과 다르다.
  시작일 환율이 없으면 원금을 원화로 정할 수 없어 원화 수익률·손익을 계산하지 않는다 (마지막 날 환율로 거꾸로 환산하지 않음).

**백엔드 연동 시 필요한 것 (제안):** 실행 취소를 진행 중 작업에서 바로 멈추는 기능과 `proposed_cancel` 같은 취소 결과 응답, 단계별 경고 전체 목록 API(요약의 2건 제한 없이),

## 15. 대화형 초기 투자조건 (목업 전용)

처음 쓰는 사용자가 챗봇처럼 필수 항목만 답해 기본 투자조건을 만든다. 백엔드 요청은 [backend-requests-profile-chat.md](./backend-requests-profile-chat.md).

**여는 법:** `?mock=1` → 목업 패널 「내 투자조건」의 「처음 사용자 (투자조건 없음)」 → 앱이 `#/profile/chat` 으로 보낸다 (또는 주소를 바로 연다).

| 항목 | 규칙 (`mocks/data/profileChat.ts`) |
|---|---|
| 질문 | 필수 11문항 고정 순서: 목적 → 처음 투자금 → 월 추가 투자 → 기간 → 성향 진단 3문항(`features/profile/diagnosis.ts`) → 성향 확인 → 투자 대상 지수(여러 개) → 종목 수 → 종목 고르는 기준(성향별 추천, `mocks/data/strategy.ts`) |
| 답 | 보기 버튼, 금액·숫자 직접 입력. 자유 문장은 받지 않는다 |
| 화면 | 메신저 창 하나: 위 막대(도우미·진행) / 대화(이 영역만 스크롤, 창 높이를 화면에 맞춰 페이지는 스크롤되지 않음) / 아래 입력줄(금액·숫자 직접 입력, 요약 단계에선 저장 버튼). 보기는 마지막 질문 바로 아래 내 쪽에 「추천 답장」처럼 뜨고, 대화는 메신저처럼 아래부터 쌓인다. 보내면 응답 전에 내 답 말풍선과 「…」를 먼저 보이고, 요약은 대화 안의 카드로 나온다. 목업의 대화 응답은 「…」가 보이도록 평소 지연의 5배(기본 0.6초) |
| 다시 묻기 | 범위 밖 금액·숫자, 없는 보기, 필수 건너뛰기 → 답을 저장하지 않고 봇이 다시 묻는다. 차례가 아닌 질문 ID 는 409 |
| 고치기 | 사용자 답 말풍선의 「고치기」 → 그 답만 다시 묻는다. 뒤의 답은 남기고(말풍선은 다시 답할 때까지 숨김), 성향 진단을 고치면 「성향 확인」도 다시 묻는다 |
| 초안 | 기본값(`features/profile/defaults.ts`)에 답을 반영. 종목 수에 맞춰 범위(±20%)·종목당 상한을 같이 정해 폼 검사(`validate.ts`)를 통과하게 한다 |
| 저장 | 요약에서 「이대로 저장」 → 기존 `saveProfile` (note 「첫 등록」). 「폼에서 세부 수정」·「폼으로 한 번에 입력」은 초안을 ui 저장소(`profileDraft`)로 넘겨 4단계 폼이 미리 채운다. 그때의 대화도 `profileChat` 에 남겨, 폼의 「대화로 이어서 하기」로 돌아오면 그 질문부터 이어 간다 (저장·「처음부터 다시」에서 지움). 대화 중간에 넘어오면 폼의 묻지 않은 단계는 「완료」로 표시하지 않는다 |
| 일반 모드 | 대화 메서드가 없으므로 처음 사용자는 4단계 폼으로 간다. 폼의 「대화로 설정하기」도 보이지 않는다 |
