# 홈 「사용 안내」 메뉴 · `tutorial-improve` 병합 안내 (2026-11-18)

팀원 브랜치 `tutorial-improve`(소개 화면 · 둘러보기 개선)와 이 브랜치 `feature/front-home-redesign`(홈 시안 3)를 합칠 때 참고할 내용이다.
이 브랜치에는 소개 화면으로 가는 **입구(메뉴 항목)만** 먼저 넣었다. 소개 화면 자체는 `tutorial-improve` 에 있다.

## 1. 문제

- `tutorial-improve`(커밋 `cea57bf` 튜토리얼 개선, `de70097` 소개 가로 슬라이드)가 하는 일
  - 소개 화면 `#/intro`(`tutorial/IntroScroll.tsx` · `FeatureSlides.tsx`, 신규). 처음 온 사람은 홈 대신 소개부터 (`introSeen()`, 한 번 보면 다시 안 뜸). 마지막 장에서 「화면 둘러보기」 또는 예시 리포트로 이어진다.
  - 둘러보기 말풍선이 입력 · 클릭 · 마우스 올림을 그림으로 보여 줌 (`Coachmark.tsx` 의 `demo`).
  - 옛 홈 제목 아래 버튼 셋: 「MyFinSight 소개」(신규) · 「처음이신가요? MyFinSight 둘러보기」 · 「리포트 보는 법 둘러보기」. 소개에서 「화면 둘러보기」로 오면 홈 둘러보기 자동 시작 (`hasHomeTourFlag` / `clearHomeTourFlag`).
- **버튼 셋이 나란히 있으면 차이가 안 보인다.** 「소개」와 「둘러보기」 중 무엇을 눌러야 할지 처음 온 사람이 알기 어렵다.
  - 소개 = MyFinSight 가 무엇을 하는지 (따로 열리는 스크롤 화면)
  - 둘러보기 = 지금 홈 화면의 각 부분 (화면 위 말풍선)
  - 리포트 보는 법 = 예시 리포트로 읽는 법
- **같은 리포트 안내를 부르는 이름이 넷이었다**: 「리포트 보는 법」(홈) · 「리포트 읽는 법」(홈 둘러보기 말풍선) · 「리포트 가이드」(안내 대화상자) · 「리포트 보는 법 둘러보기」(예시 리포트 화면 · 실행 화면). 처음 쓰는 사람은 같은 것인지 알 수 없다.
- 두 브랜치 모두 `0fce140` 에서 갈라졌고, 같은 파일 두 개를 서로 다르게 고쳐 **병합 충돌**이 난다.
  - `Front/src/features/home/HomeScreen.tsx`: 저쪽은 옛 홈에 3곳 덧붙임, 이쪽은 시안 3으로 거의 새로 씀. 저쪽 판은 이쪽에서 지운 `SectorTrendsBox` 를 불러와 그대로 고르면 빌드가 깨진다.
  - `Front/src/features/tutorial/homeSteps.ts`: 저쪽은 옛 8단계에 `demo` 추가, 이쪽은 단계 재배치 · 이름 변경.
  - `App.tsx` · `router.ts` 는 자동 병합된다.

## 2. 결정

- **병합 순서 (방법 A)**: `tutorial-improve` 가 먼저 main 에 들어가고, 그다음 이 브랜치에서 main 을 받아 **이쪽 파일 기준**으로 충돌을 정리한다. 그 전에는 `tutorial-improve` 브랜치를 건드리지 않는다.
- **도움 셋을 버튼 하나 + 메뉴로** (사용자 결정, 후보: 버튼 하나+메뉴 / 이름만 바꾸기 / 리포트 보는 법을 리포트 쪽으로 / 그대로 두기). 「새 분석」 카드 머리 오른쪽에 「사용 안내」 하나, 누르면 아이콘 + 이름만 한 줄씩:

  | 항목 | 동작 |
  |---|---|
  | ✦ 서비스 소개 | `#/intro` |
  | ◎ 홈 화면 둘러보기 | 홈 둘러보기 시작 |
  | ▤ 예시 리포트 둘러보기 | `#/tutorial` |

- 처음엔 「이 화면 둘러보기」였으나 「이 화면」이 어디인지 모호하다는 의견으로 「홈 화면 둘러보기」.
- 처음엔 항목 아래 작은 설명 줄(「MyFinSight가 무엇을 하는지 한눈에 봐요」 등)을 뒀으나, 이름만으로 셋이 구분되고 메뉴가 길어져 지움 (사용자 결정).
- **리포트 안내 이름은 「예시 리포트 둘러보기」 하나로** (사용자 결정). 예시라서 리포트가 없어도 볼 수 있다는 점이 드러나고, 「홈 화면 둘러보기」와 짝이 맞고, 누르면 실제로 예시 리포트가 열린다.
  - 단, 이미 예시 리포트를 보고 있는 화면(`tutorial/TutorialScreen.tsx`)의 버튼은 「리포트 보는 법 둘러보기」 → **「단계별로 둘러보기」** (같은 이름이면 「보고 있는데 또 둘러보기?」로 읽힘).
- **버튼 이름은 「사용 안내」** (사용자 결정). 처음엔 「사용 안내」였으나, 리포트 읽는 법을 다시 보러 온 사람이 누를 생각을 하기 어렵고 안내 문구의 「언제든 다시 볼 수 있습니다」와도 부딪혀 바꿈. 앞에 ? 아이콘.

## 3. 수정

- **`Front/src/features/home/HelpMenu.tsx`(신규)**: 「사용 안내」 버튼과 메뉴. 토큰 색(`surface` · `sunken` · `main` · `sub`), 테두리 없이 그림자 토큰 `shadow-overlay`. Esc · 바깥 클릭 · Tab 으로 메뉴 밖에 초점이 나가면 닫힘, 열면 첫 항목에 초점, 위아래 화살표로 이동, 닫히면 초점이 버튼으로 돌아감. 공용 `ui/Menu` 는 아직 옛 `slate` 색 · 테두리라 따로 만들었다 (공용 메뉴를 토큰으로 바꾸면 합칠 수 있음).
- **`features/home/HomeScreen.tsx`**: 카드 머리 버튼 셋 → `HelpMenu` 하나. 「서비스 소개」는 지금 `window.location.hash = "#/intro"` (이 브랜치만으로는 경로가 없어 「페이지를 찾을 수 없습니다」, 코드에 주석).
- 이름 통일 「예시 리포트 둘러보기」: `HomeScreen.tsx`(메뉴), `run/RunScreen.tsx`(「기다리는 동안 예시 리포트 둘러보기」), `tutorial/GuidePrompt.tsx`(대화상자 제목 「리포트 가이드를 보시겠습니까?」 → 「예시 리포트를 둘러보시겠습니까?」).
- 문장
  - `tutorial/homeSteps.ts` 마지막 단계: 「리포트 읽는 법은 위쪽 「리포트 보는 법」에서 볼 수 있습니다.」 → 「리포트를 어떻게 읽는지는 「새 분석」 카드 위 「사용 안내」 메뉴에서 예시 리포트로 볼 수 있습니다.」 (한 문장에 이름 둘, 「위쪽」이 모호, 괄호 겹침)
  - `GuidePrompt.tsx` · `ExampleReportParts.tsx`: 「홈의 「리포트 보는 법 둘러보기」에서…」 → 「홈의 「사용 안내」 메뉴에서 언제든 다시 볼 수 있…」. 예전 문구는 홈에 있지도 않은 버튼 이름을 가리키고 있었음.
  - `tutorial/exampleReport.ts` 예시 리포트 요약: 「리포트 보는 법을 익히는」 → 「리포트 읽는 법을 익히는」.
- 테스트 `home/home.test.tsx`: 메뉴 항목 3개 · 열면 첫 항목 초점 · Esc 로 닫고 버튼으로 초점 · 메뉴 밖으로 초점이 나가면 닫힘 · 「예시 리포트 둘러보기」 → `#/tutorial`, 홈 둘러보기는 메뉴를 거쳐 시작. `tutorial.test` · `guidePrompt.test` 는 바뀐 이름으로.

## 4. 알아 둘 것 (병합할 때 할 일)

`tutorial-improve` 가 main 에 들어온 뒤 이 브랜치에서 `git merge origin/main` 하고 아래대로 정리한다.

1. **`HomeScreen.tsx` = 이쪽 파일 그대로** + 저쪽 기능 두 가지만 옮긴다.
   - 저쪽 버튼 셋(「MyFinSight 소개」 등)은 가져오지 않는다. 이쪽 「사용 안내」 메뉴가 대신한다.
   - 메뉴의 「서비스 소개」 `onClick` 을 `navigate({ page: "intro" })` 로 바꾸고 주석을 지운다.
   - 둘러보기 자동 시작: `tour` 초기값을 `hasHomeTourFlag() ? 0 : null` 로, `useEffect(() => clearHomeTourFlag(), [])` 추가 (둘 다 `tutorial/IntroScroll` 에서 import).
   - 저쪽 판의 `SectorTrendsBox` import 는 가져오지 않는다 (이쪽에서 `HomeInfo` 탭으로 옮기고 파일을 지움).
2. **`homeSteps.ts` = 이쪽 단계 · 제목 · 문구** + 저쪽 `demo` 만 단계 이름(target)에 맞춰 붙인다.

   | 단계(target) | demo |
   |---|---|
   | `home-idea` | type (입력하는 모습) |
   | `home-examples` | hover `"button"` |
   | `home-detail`, `home-submit` | click |
   | `home-trends` | hover `"ul button, [data-tour='home-trend-prompt']"` |
   | `home-profile` | click, label 「내 투자조건 보기」 |
   | `home-reports` | click, label 「전체 보기」 |

   demo 의 click 은 그림만 보여 주고 실제로 누르지 않는다. 이쪽 둘러보기는 단계에 따라 오른쪽 탭을 자동으로 바꾸므로(`TOUR_TAB`), 탭이 바뀐 뒤 demo 대상이 화면에 있는지 확인한다.
3. **`IntroScroll.tsx` 옛 버튼 이름** (이쪽에서 이름을 바꿈)
   - 34행 설명 「분석 시작」 → 「이 조건으로 분석 실행」
   - 158행 가짜 버튼 「투자조건 확인하기」 → 「분석 시작하기」
   - 211행 가짜 버튼 「분석 시작」 → 「이 조건으로 분석 실행」
   - 마지막 장 선택지(약 382·385행): 「예시 리포트 먼저 보기」 → 「예시 리포트 둘러보기」, 「화면 둘러보기」 → 「홈 화면 둘러보기」 (홈 메뉴와 같은 이름)
   - 마지막 줄(약 389행) 「이 소개는 홈의 「MyFinSight 소개」에서 언제든 다시 볼 수 있습니다.」 → 「…홈의 「사용 안내」 메뉴에서…」
4. **색**: `IntroScroll.tsx` 는 `violet-*` · `slate-*` · `blue-*` 를 직접 쓴다 (약 50곳). `slate-*` 는 `styles/tokens.css` 의 별칭 블록 덕에 토큰 색으로 바뀌어 보이지만, `violet-*` 배경은 다른 화면과 톤이 다르다. 토큰(`accent` · `tint` · `canvas` 등)으로 바꿀지는 따로 정한다.
5. 소개 화면의 「보충 질문」 설명(「한 번에 하나씩 묻습니다」)은 홈 대화창도 한 번에 하나씩 묻기 때문에 그대로 맞다.
