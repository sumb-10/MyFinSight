# 데이터 모델과 로컬 통합

## 1. 기술 방향

기존 React 프레임워크와 컴포넌트 구조를 우선 사용한다. TypeScript가 지원되면 공통 타입을 활용한다. 중복 화면보다 공통 컴포넌트·포맷터·데이터 모델을 정리한다. 실제 코드 구조를 읽기 전 새 프레임워크나 의존성 버전을 지정하지 않는다.

화면은 로컬 데이터 서비스 인터페이스를 사용한다. 처음에는 일관된 고정 자료와 브라우저 저장으로 모든 상호작용을 독립 실행한다. 이후 localhost의 분석 API 어댑터를 추가해도 화면 컴포넌트를 대규모 변경하지 않도록 한다. 외부 애플리케이션 서버·클라우드 DB·원격 인증·텔레메트리를 추가하지 않는다.

시장 자료 수집과 LLM API 호출은 향후 분석 기능의 별도 연결이다. localhost 실행이라는 사실은 모든 외부 분석 자료가 자동으로 오프라인 제공됨을 의미하지 않는다. 고정 자료 모드의 정상 흐름은 인터넷 없이 동작해야 한다.

## 2. 공유 데이터 객체

아래는 화면 설계를 위한 모델 책임이다. 기존 Python 모델을 그대로 대체하는 확정 API 스키마는 아니다. 실제 통합에서는 이름·단위·버전 변환을 어댑터에서 정한다.

| 객체 | 주요 내용 | 보존·연결 원칙 |
| --- | --- | --- |
| Profile | 금액·기간·산출/최종 성향·손실 감내·관심·선호·제약 | 하나만 저장, 변경은 다음 분석에 적용 |
| AnalysisRequest | 원래 아이디어, 모드, 기준 리포트, 질문·답변 | 신규·재분석·수정의 출발점 구분 |
| EffectiveConditions | 프로필 사본, 이번 변경값, 확정 조건 | 분석 당시 값을 리포트와 함께 보존 |
| StrategySpec | Universe·선정·비중·제약·재조정·계산 조건 참조 | 사전 구현 규칙에 매핑, 버전·해시 |
| Allocation | 기준일, 종목, 원시·최종 비중, 상한·금액·환율 | 규칙 실행 결과와 표시값 연결 |
| EvidenceRecord | 문서·출처·발표일·취득일·관련 사실·발췌·URL | 정성 자료와 정량 계산 자료 구분 |
| ResearchClaim | 주장, 근거 ID, 사실/해석, 영향받은 결정 | 근거 없는 주장을 본문에 넣지 않음 |
| CalculationConditions | 기간·통화·비교지수·비용·무위험수익률·체결 가정 | 모든 후보와 비교안에 동일 적용 |
| Performance | 날짜별 평가액·수익률·낙폭·비교지수·지표 | 차트·카드·본문이 같은 결과를 참조 |
| ExecutionRecord | 단계·상태·시각·요약·출처·실패 사유 | 실제 작업 기록, 내부 추론문 재현 아님 |
| Report | ID, 요청·조건·규칙·자료·배분·성과·본문·기록·날짜 | 과거 객체 불변, 인용 ID 연결 |
| PaperPortfolio | ID, 원본 Report ID, 시작일·자본·구성·규칙·시계열·갱신 상태 | 기존 추적 보존, 개별 상세 |
| RevisionComparison | 원본·수정 Report ID, 공통 계산 조건, 변화·비교 결과 | 원본의 과거 지표와 재비교 지표 구분 |

저장 상태는 분석 결과의 유효성과 분리한다. 결과가 유효하지만 저장에 실패한 경우도 표현할 수 있어야 한다. 과거 리포트에 계속 바뀌는 전역 프로필·공통 본문·전체 공통 차트를 직접 연결하지 않는다.

## 3. 정성 DB와 리포트의 관계

정성 자료는 기업 공시·실적발표·경영진 설명·산업자료·뉴스·규제·공급망·경쟁 자료 등으로 구성할 수 있다. 기록은 자료 원문 정보와 보고서에서 추출한 사실을 구분한다. 긴 원문 전체를 UI에 복제하지 않고 필요한 발췌와 위치를 연결한다.

판단은 하나 이상의 근거 기록을 참조한다. 예를 들어 “공급 확대가 확인됐다”는 사실과 “수요 증가가 매출로 이어질 여지가 있다”는 해석은 별개다. “따라서 기업을 후보에 포함했다”는 결정까지 연결할 때 실제 후보 선정 과정이 그 기록을 사용했는지 확인한다.

발표일·자료 기준일·수집시각은 다르다. 수집시각이 최신이어도 오래된 기록을 최신 사업 전망으로 표시하지 않는다. 분석 기준 이후 발표된 자료를 당시 리포트나 역사적 선정 근거에 넣지 않는다.

완성된 화면을 만들기 위해 리서치 고정 자료를 공급할 수 있지만, 실제 출처를 주장한다면 검증된 기록을 제공해야 한다. 자료가 없는 경우 출처를 만들지 않는다. 필요한 정성 자료가 미연결이면 구현 문서에 이슈를 남기고, 성공 리포트에 가짜 기업 판단을 채우지 않는다.

합성 수치와 실제 리서치 자료를 함께 사용할 때는 정성 근거와 수치 실험의 성격을 참고자료에서 구분한다. 내부 fixture 분류를 모든 화면의 배지로 노출하지 않는다.

**공시 근거 (2026-10-25 라운드 4).** 정성 자료는 뉴스 헤드라인(`ev<news_id>`)과 공시 사건(`dc<disclosure_id>`) 두 종류다. 공시는 SEC EDGAR(8-K·10-Q·10-K)와 DART 의 사건 목록으로, 사건 종류·양식·항목·접수일·**이용 가능일**(`available_on`)만 있고 본문은 없다. 구성일 d 의 뷰에는 `[d−45일, d)` 창의 공시가 뉴스(14일)보다 **앞선 주 근거**로 들어가고, 공시만 인용한 뷰의 신뢰도는 0.25 로 묶인다(설정). 리포트 §2 시장 분석·§3 기업별 근거(90일 사건 요약)·§4 타임라인(리밸런싱일별 공시 건수)에도 쓴다. 공시는 사건의 존재만 알려 주며 결과(좋았다·나빴다)를 뜻하지 않는다 — 화면 문구도 그렇게 쓴다.

**리포트 문서 v2 (`doc_version: 2`).** `summary`(대시보드), `evidence`(인용된 근거만), `evidence_summary{total, cited, by_kind}`, 블록 공통 `group_ko`/`group_open`/`src`, 새 블록 `evidence_ref`·`weights_compare`·`timeline`·`companies`, 시계열이 600점을 넘으면 `datasets.sampling`(stride, 첫/끝·최대낙폭 고점·저점 고정). 보조 조회: `GET /reports/{id}/evidence`(페이지·필터), `/evidence/{eid}`(한 건 + 인용 문장), `/checkpoints/{seq}`(시점 상세), `/series`(전체 해상도). 옛 v1 문서는 서버(`present_doc`)와 화면(`lib/reportNormalize.ts normalizeDoc`)이 모두 변환한다: `evidence` 블록 → `evidence_ref`, `checkpoints` → `timeline`, 있는 정보로 `summary` 유도. 응답은 gzip 으로 온다.

## 4. 저장과 재접속

프로필, 완료 리포트, 모의투자와 관계를 localStorage 또는 IndexedDB에 저장한다. 브라우저 저장은 클라우드·운영체제 파일·브라우저 간 동기화가 아니다. 정상 화면에 반복 안내하지 않되 관련 설정과 오류는 정확하게 표현한다.

저장 서비스는 검증·쓰기 실패·읽기 실패를 반환해야 한다. 실패 시 원래 프로필과 기존 결과를 보존한다. 완료되지 않은 분석을 저장된 성공 리포트로 복원하지 않는다. 취소·중단된 분석은 명시적인 재시작 없이 다시 실행하지 않는다.

리포트·포트폴리오·수정안에는 개별 ID를 발급한다. 추적 객체와 수정 결과는 기준 리포트 ID를 저장한다. 페이지 reload 후에도 해당 연결이 유지되어야 한다.

향후 스키마가 달라지면 버전과 마이그레이션을 고려한다. 기존 데이터를 읽을 수 없으면 이유와 복구 방법을 알리고 임의 초기화하지 않는다.

## 5. 검증과 데이터 품질

- 실행 전: 필수 항목·값 범위·지원 규칙·프로필 제약을 검사한다.
- 실행 후: 종목 유효성·제외 조건·개별 상한·총비중 100%를 검사한다.
- 결과 표시 전: 규칙·비중·금액·시계열·지표·본문 수치가 실제 결과와 일치하는지 검사한다.
- 필수 자료 실패와 일부 후보 제외를 구분한다. 사용자가 지목한 종목의 자료 실패는 임의 제외로 성공 처리하지 않는다.
- 현재 UC의 데이터 커버리지 기준은 95%이며, 가격·비교지수 필수 자료 정책을 따른다. 실제 어댑터 계약을 확인해 적용한다.
- 뉴스·재무는 기존 백엔드에서 보조 자료다. 부족해도 가격 백테스트가 가능할 수 있으나 정성 판단을 만들어내는 근거는 되지 않는다.
- 결측값을 LLM 수치로 채우지 않는다. 기존 명세는 연속 1거래일 이내 직전값 보간만 허용한다.
- 후보가 실패하면 실패 상태를 기록한다. 일부 후보가 남으면 검증된 결과만 제공하고, 모두 실패하면 분석 실패로 처리한다.

## 6. 금액·날짜·성과 정합성

계산 기준 통화는 USD, 사용자 입력·보조 표시 금액은 KRW다. 환율은 `1 USD = X KRW`처럼 방향을 명확히 한다. 원화 투자금을 USD로 바꿀 때 해당 환율로 나누며, 환율과 적용 기준일을 표시한다.

사용자 투자기간은 앞으로의 보유 의도다. 과거 백테스트 기간과 모의투자 추적 기간은 별개 필드다. 3년 투자 의도가 있다고 모든 차트를 자동으로 과거 3년으로 표시하지 않는다.

고정 자료 모드의 시장 기준일은 한 값으로 관리한다. 리포트마다 작성일·자료 기준일·배분 기준일을 갖고, 모의투자는 별도의 시작일·최신 관측일을 갖는다. 미래 관측값을 표시하지 않으며 추적 기간은 실제 두 날짜에서 계산한다. 리포트 작성일은 사용 자료 발표일·관측일보다 앞설 수 없다.

차트 끝값과 누적수익률 카드, 평가액과 손익, 낙폭 시계열과 MDD, 표 비중과 배분 금액은 일치해야 한다. 비교지수는 같은 시작·종료 날짜를 사용한다. 원안·수정안도 같은 계산 조건을 사용한다.

역사적 비중 산출에는 해당 거래 시점에 이용 가능한 자료만 쓴다. 기존 백엔드의 전일 종가까지 신호를 계산하고 당일 종가에 체결하는 가정은 실제 실행 결과와 맞춰 설명한다. 현재 구성종목을 과거로 확장한 편향은 방법론에서 보존한다.

## 7. 표시 규칙

| 항목 | 규칙 |
| --- | --- |
| 수익률·비율 지표 | 소수 둘째 자리, 필요한 경우 +·− 부호 |
| 비중 | 소수 첫째 자리 |
| 원화 | 원 단위 정수와 천 단위 쉼표 |
| 달러 | 소수 둘째 자리 |
| Sharpe | 소수 둘째 자리 |
| 날짜 | YYYY-MM-DD |
| 수익률 차이 | %p, 수익률 %와 구분 |
| 반올림 | ROUND_HALF_UP, 표시 단계에서만 적용 |

원본 정밀도는 유지한다. 표시 비중을 합계 100.0%에 맞추려고 원본 값을 바꾸지 않는다. 작은 표시 반올림 차이가 있으면 간결하게 설명한다. 계산 불가 값은 사유와 함께 표시한다.

모든 차트·표는 기간, 단위, 필요한 통화, 기준일과 근거 접근을 갖는다. 내부 ID·개발 용어 대신 사용자가 이해할 수 있는 자료명과 계산 설명을 쓴다.

## 8. 서비스 인터페이스 책임

프론트엔드 서비스는 프로필 조회·저장, 조건 준비·질문, 확정 요청 실행·취소, 리포트 조회·저장, 모의투자 활성화·조회·갱신, 수정안 비교를 지원한다. 실제 URL과 함수 이름은 기존 저장소에서 정한다.

고정 자료 어댑터와 로컬 API 어댑터는 같은 데이터·오류 계약을 따른다. 로컬 API가 연결되지 않으면 실제 분석 성공으로 위장하지 않는다. 정상·일부 완료·주요 실패 상태를 재사용 가능한 자료로 제공하고, 테스트 상태 전환은 정상 제품 동선에서 분리한다.
