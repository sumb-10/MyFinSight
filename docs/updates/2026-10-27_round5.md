## 1. 검증 규칙 재설계 (`m5_backtest_report/validate.py`, `matched.py`, `backtest.py`)

- **R1 최대낙폭 = 표시(flag) 규칙.** 넘어도 `fail` 이 아니라 `flag`(허용 초과). 포트폴리오 `fail` 은 내부 점검(R4·R5·R8) 만.
- **허용 낙폭 표시 = 사용자 입력값.** ×0.8(손실 시 매도)·×0.9(경험 없음) 보정은 **낙폭 맞춤안의 목표**로만 쓴다(`risk_params.effective_max_drawdown`, `crit.match_target`). 조건 확인 화면의 행 이름은 "낙폭 맞춤안 목표". 서식은 소수 1자리(6.4%).
- **추천은 항상 하나.** 순위 키 = (무결성 실패, 목표수익 미달, 비교지수 열위, 허용 낙폭 초과 구간(5%p 단위), 보수 성향이면 낙폭 맞춤안 우선, −Sharpe, 낙폭). 결론 라벨 `추천` / `추천(주의: 허용 낙폭 초과 (x%p) · 목표수익 미달 · 비교지수 하회)` / `구성 불충분`(기준 구성 투자 비율 < 50%). 사유 문장은 사실만(info 규칙을 "만족"으로 세지 않고, Sharpe 음수면 "가장 덜 나쁨").
- **낙폭 맞춤안(`dd_match_<기준>`) = 정식 후보.** 11 단계가 기준 비중 템플릿 + `wf_bl_news` 를 기준으로, 폐형식 씨앗 → **실제 리밸런싱 일정**으로 이분 탐색(0.5%p 올림, 검증·+1%p 보정) 해 MDD ≤ 목표가 되는 현금 비율을 찾는다. 이름은 총 투자 비중으로("낙폭 맞춤안 (주식 50% + 현금 50%, 역변동성비중 기준)"). 예전 현금 혼합안(`alternatives`, 일별 리밸런싱 가정으로 비율을 풀어 실제 일정에서 목표를 넘기던 문제) 삭제. 모의투자(`paper.py`)·비교(`compare.py`)·번들 검증이 새 id 를 받는다.
- **BL 위험회피 δ 에 허용 낙폭 반영**: δ × clip(0.20 / 허용 낙폭, 0.75~1.5) (`market_model.py`, `PortfolioSettings.delta_dd_ref_tol`). 계산 조건 표에 "× 낙폭 배수" 표시.
- **뷰 적중률 둘**: 기존 12개월 지평 + **다음 리밸런싱 창** 적중률(`view_hit_ratio_next_rb`, `backtest_metrics.view_diagnostics_next_window`). 대시보드 "뉴스 반영 효과" 카드(뉴스 반영 구성 vs 기준 비중의 CAGR·낙폭 차이, 두 적중률, 뷰 수, 기준 비중 유지 횟수) — 추천이 다른 포트폴리오여도 보인다.
- 짧은 창: `min_annualize_days` 252 → 378(1.5년). 미만이면 KPI 는 기간 수익률, R2/R7 은 참고.
- 결론 옆 안내: `summary.verdict.period_note_ko`(요청 3년 중 1.0년만 평가 — 사유), `notices_ko`(사용자 공지 최대 3건), `cautions_ko`.
- 한국 종목이 있으면 백테스트 가정·한계에 "모든 성과·지표는 미국 달러 환산 가격 기준(환율 변동 포함)" 한 줄.

## 2. 대화 보강 (`m1_request/dialog.py`, 새 `m1_request/precheck.py`)

- **실행 전 점검(precheck, LLM 없음)**: 기준일·백테스트 시작일에서 후보 검색 + 선정 지표 보유 수를 센다(01 단계와 같은 가격 선적재, 서명이 같으면 재사용). 결과는 `DialogState.precheck`.
- **질문 2종**(kind `feasibility`, 코드 규칙, LLM 질문보다 앞): ① 후보 부족 — "종목 수를 n개로 줄이고 종목당 상한을 x%로 올려 전액 투자" / "테마를 넓혀 다시 해석" / "그대로 진행(현금이 남을 수 있음)"; ② 창 축소 예상 — "기간 유지(시작 때 n종목으로 평가)" / "백테스트 기간을 y년으로" / "종목 수를 n개로". 보기는 `patch`(여러 필드 동시 override) 또는 `clarification`(아이디어 보충) 을 가진다(`QuestionOption` 확장).
- **보기 1개 질문 폐기**: HARD 검증으로 보기가 하나만 남으면 묻지 않는다(재실행·수정 대화에서 "프로필대로: 고배당" 하나짜리 질문이 나오던 문제).
- **질문 상한 → ready**: 상한에 닿아도 막지 않고 남은 항목을 기본값으로 두고 확정할 수 있게 한다(`blocked_reason_ko` 로 사유 표시).
- **종목 수 자동 보정**: 목표만 바꾸면 최소·최대를 맞추고, 상한 × 최소 < 투자 비율이면 종목당 상한도 함께 올린다(HARD 오류 대신).
- 질문에 `field_label_ko`(원시 경로 대신 라벨).
