**원인**
1. 해석(02_intent) 프롬프트에 `context_package()` 가 넣는 "최근 실행 3건 요약"이 들어간다. 1차와 재실행 사이에 실행 5건이 생겨 프롬프트가 달라졌고, 프롬프트 해시 캐시(C-04)가 비껴갔다.
2. LLM 온도(`temperature`)가 지정되지 않아 같은 프롬프트라도 공급자 기본값으로 답이 흔들린다. 재실행에서는 `idea_value` 를 템플릿에 없는 `dividend_growth` 로 적었다.
3. 코드 규칙 질문(`_conflict_proposals`)이 만든 "아이디어대로: dividend_growth" 보기는 HARD 검증에 걸려 빠지고, 남은 보기 하나로 질문이 나갔다(`allow_free_text=False`). 보기가 하나뿐인 질문은 묻지 않거나 자유 입력을 열어야 한다.

**판정에 쓴 근거**: 결정론이 깨진 지점은 LLM 호출(캐시 밖)이고, LLM 뒤 단계(선정·구성·백테스트·검증·리포트 숫자)는 입력이 같으면 같은 결과를 낸다는 것이 `test_sequential_run_gives_identical_results`(병렬 vs 순차, `13_results` 전체 동일)로 보장된다. 다만 실제 서비스에서는 이력 요약 때문에 캐시가 거의 맞지 않으므로 "같은 요청 두 번 → 같은 리포트"는 지켜지지 않는다.
